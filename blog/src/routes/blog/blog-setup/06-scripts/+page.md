仕組みはできた。あとは続けられるかどうか。

## 手で書くと続かない

記事を 1 本足すのに、最初はこうしていた。

1. フォルダを作るコマンドを打つ
2. ファイルを作る
3. `---` の囲みを手で書く（題名・日付・概要）
4. `git add` と `git commit` と `git push`

毎回これをやる気にはならない。打ち間違えると frontmatter が壊れて、記事が一覧に出なくなる。

連載だと輪をかけて面倒だった。フォルダ名を手で打つので、`blog-setup` を `blog_setup` と間違えると別の連載になってしまう。何回目かも自分で数える必要がある。

## 作る道具

`scripts/new-post.mjs` を置き、`package.json` に登録した。

```
npm run new
```

最初に、どこに書くかを聞かれる。

```
どこに書きますか。
  0) 単独の記事（連載にしない）
  1) blog-setup  （6 本 → 第 7 回）
  2) k8s  （3 本 → 第 4 回）
  n) 新しい連載をはじめる

番号:
```

既存の連載は、フォルダを見て自動で並ぶ。番号を選べば、連載名も回数も自動で決まる。

既にあるフォルダ名から次の番号を計算しているので、`07-` のような連番が自動で付く。打つのは題名と概要と、URL の後半だけ。

```
題名: 無料でブログを作る (7) RSS を作る
概要（1 行）: 購読できるようにする。
URL の後半（英字。例 rss）: rss
```

これで `src/routes/blog/blog-setup/07-rss/+page.md` ができ、索引が更新され、エディタが開く。本文を書くだけ。

新しい連載を始めるときは `n` を選んでフォルダ名を答える。単独の記事なら `0`。

## 公開する道具

`scripts/publish.mjs` も同じように置いた。

```
npm run publish -- "記事: RSS を作る"
```

`add` と `commit` と `push` をまとめて実行する。変更が無ければ何もせず終わる。

## 結果

| | 前 | 後 |
|---|---|---|
| 書く場所を決める | フォルダ名と回数を手で打つ | 番号を選ぶ |
| 作る | コマンド＋手書き 4 行 | 題名と概要を答える |
| 公開 | コマンド 3 つ | コマンド 1 つ |

やることは同じだが、打つ量と間違える箇所が減った。続けられるかどうかはここで決まる。
