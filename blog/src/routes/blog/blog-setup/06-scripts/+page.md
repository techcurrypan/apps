## 手で書くと続かない

記事を 1 本足すのに、最初はこうしていた。

1. フォルダを作るコマンドを打つ
2. ファイルを作る
3. `---` の囲みを手で書く（題名・日付・概要）
4. `git add` と `git commit` と `git push`

毎回これをやる気にはならない。打ち間違えると frontmatter が壊れて、記事が一覧に出なくなる。

## 作る道具

`scripts/new-post.mjs` を置き、`package.json` に登録した。

```
npm run new
```

題名と概要と URL 名を聞かれる。答えると、フォルダもファイルも frontmatter も日付も入った状態で作られ、索引が更新され、エディタが開く。本文を書くだけ。

URL 名に `k8s/01-pod` のように `/` を入れれば、入れ子のフォルダになる。連載はこれでまとめる。

## 公開する道具

`scripts/publish.mjs` も同じように置いた。

```
npm run publish -- "記事: Kubernetes 入門"
```

`add` と `commit` と `push` をまとめて実行する。変更が無ければ何もせず終わる。

## 結果

| | 前 | 後 |
|---|---|---|
| 作る | コマンド＋手書き 4 行 | `npm run new` に答える |
| 公開 | コマンド 3 つ | コマンド 1 つ |

やることは同じだが、打つ量と間違える箇所が減った。

## つまずいた所（全部）

### 開発サーバーが古い内容を覚えている

frontmatter を変えたのに画面に出ない。索引は起動時に作られるので、**記事を足したり frontmatter を変えたら開発サーバーを再起動する**。本文だけの変更なら不要。

### PowerShell で角かっこのフォルダが作れない

`[tag]` のような名前は、PowerShell ではワイルドカードとして解釈される。`-LiteralPath` を付けると通る。

### package.json が壊れた

PowerShell の `Set-Content -Encoding UTF8` は、ファイルの先頭に BOM という見えない印を付ける。JSON としては不正になり、ビルドが「Unable to read package.json」で止まる。

BOM なしで書くには次のようにする。

```
[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding $false))
```

`.ts` や `.svelte` は大抵問題にならないが、`.json` は厳密に弾かれる。

### 長い文を PowerShell に貼ると途中で切れる

記事のような長い文を貼り付けると、タブ文字が補完を起動したり、途中で切れたりする。**長い文はエディタで直接書く**のが確実。

### GitHub の認証が別アカウントのまま

複数アカウントを使っていると、古い方の認証が使われて `Permission denied` になる。リポジトリごとに使うアカウントを指定できる。

```
git config credential.https://github.com/.username <アカウント名>
```

### 外部の Actions が禁止されている

組織のリポジトリでは既定で禁止されていることがある。設定の Actions permissions で許可する。

### 型定義ファイルが GitHub 側に無い

`wrangler types` の生成物はリポジトリに入れていないので、配信の前に生成する手順を足す。

### workers.dev のサブドメインが未登録

最初の配信で止まる。Cloudflare のダッシュボードで 1 回登録する。
