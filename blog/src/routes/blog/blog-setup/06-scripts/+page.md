ここまでで公開はできる。ただ記事を 1 本足す手順が多すぎる。

**この回が終わると**、記事を書くのに覚えるコマンドが 4 つだけになる。

**前提**: 第 5 回で push による公開が通っていること。

## 今の手順

記事を 1 本足すのに、これだけやっていた。

1. フォルダを作る（連載なら第何回かを数えて、番号付きの名前を決める）
2. その中に `+page.md` を作る
3. frontmatter を 3 行書く（日付は今日の日付を調べて書く）
4. 本文を書く
5. dev サーバを止めて起動し直して確認する
6. `git add` して `commit` して `push` する

数えるところと、日付を書くところ、フォルダ名を決めるところが毎回面倒だった。しかも手で作るので、PowerShell でファイルを作ろうとして壊したことが何度もある（第 10 回）。

## 畳んだ後

```bash
npm run new      # 雛形を作る
npm run dev      # 書きながら確認する
npm run check    # 公開前の検査
npm run publish -- "コミットの説明"
```

4 つだけ。

## npm run new

`scripts/new-post.mjs` を呼ぶ。対話で聞いてくる。

```
どこに書きますか。
  0) 単独の記事（連載にしない）
  1) blog-setup  （10 本 → 第 11 回）
  n) 新しい連載をはじめる

番号:
```

**既にある連載が一覧に出て、第何回かも自動で数える。** 数えなくてよくなったのがここ。

続けて聞かれるもの。

| 聞かれること | 例 |
|---|---|
| 題名 | 無料でブログを作る (7) 記事が増えても重くしない |
| 概要（1 行） | 索引を組み立て時に作る理由 |
| URL の後半（英字） | scale |

URL の後半を空で通すと `part7` のような名前になる。意味のある名前にしたいときだけ打つ。

できるもの。

```
作成しました: src/routes/blog/blog-setup/07-scale/+page.md
URL: /blog/blog-setup/07-scale
```

- フォルダ名の番号は自動（`07-`）
- 日付は今日の日付が入る
- 索引も作り直される
- VS Code が開く

あとは本文を書くだけ。

### 中身の要点

やっていることは 3 つ。

1. `src/routes/blog/` の下を見て、**フォルダの中に `+page.md` があるもの**を記事、無いものを連載と判断する
2. 連載の中のフォルダ名から番号を拾い、最大値 + 1 を次の回とする
3. frontmatter 付きの `+page.md` を書き、索引を作り直して、エディタで開く

```javascript
const isPost = (dir) => existsSync(join(dir, '+page.md'));
```

この 1 行で連載と記事を区別している。設定ファイルを持たせずに済むので、フォルダを作るだけで連載が増える。

### 新しい連載をはじめるとき

番号のところで `n` を選ぶと、連載のフォルダ名を聞かれる。英字で短いものにする（`k8s`、`docker`）。これが URL にもなる。

第 1 回として作られる。

## npm run dev

手元で確認する。ここは変えていない。

**記事を新しく作ったときと、frontmatter を書き換えたときは、止めて起動し直す。** 索引を起動時に作るため。

本文だけの書き換えなら、保存すると自動で画面に反映される。

## npm run check

公開前の検査。第 5 回で説明したもの。

```bash
npm run check
```

`found 0 errors` を確認してから公開する。

初めて動かすときだけ、先に `npm run gen` が必要。

## npm run publish

`scripts/publish.mjs` を呼ぶ。

```bash
npm run publish -- "第 7 回を追加"
```

`--` の後ろがコミットの説明になる。省くと「記事を更新」になる。

中身はこれだけ。

```javascript
run('git add -A');
run(`git commit -m "${msg}"`);
run('git push');
```

変更が無ければ「変更はありません。」と出て何もしない。

### 注意

Git の操作は**リポジトリ全体**に対して行われる。`blog/` の外で何か触っていると、それも一緒に commit される。

ブログだけを公開したいときは、先に `git status` で何が入るか見る。

## npm run index

4 つには入れていないが、もう 1 つある。

```bash
npm run index
```

索引を作り直す。`npm run new` が自動で呼ぶので普段は打たない。frontmatter を手で書き換えたときだけ使う。

## なぜスクリプトにしたか

手で作っていたときの失敗が多かった。

- フォルダ名の番号を間違える
- 日付を昨日のまま書く
- `summary` を書き忘れて一覧が空になる
- PowerShell で長い本文を貼ろうとして途中で壊れる

**毎回同じことをするなら、そこは覚える対象ではなくコマンドにする。** 覚えることが減った分だけ、書く方に力が向く。

## ここまでの確認

- `npm run new` で雛形ができ、第何回かを数えなくてよい
- `npm run publish` で公開まで届く
- 覚えるコマンドが 4 つになった

次は、記事が増えても重くならない仕組みを作る。
