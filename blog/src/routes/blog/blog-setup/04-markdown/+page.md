記事を書けるようにする。目標は「ファイルを 1 つ置くだけで、一覧にもタグにも自動で載る」こと。

## 記事を 1 本置く

`src/routes/blog/hello/+page.md` を作る。

```
---
title: 最初の記事
date: '2026-11-07'
summary: 概要を 1 行で。
---

本文を Markdown で書く。
```

`http://localhost:5173/blog/hello` で開ける。フォルダ名が URL になる。

先頭の `---` で囲んだ部分を frontmatter という。記事の属性をここに書く。

**日付は引用符で囲む。** 囲まないと日付型として解釈され、後で並び替えるときに壊れる。

## 記事の索引を作る

一覧を作るには、全記事の題名と日付を集める必要がある。

Vite には `import.meta.glob` という、条件に合うファイルをまとめて読む仕組みがある。これが一番手軽だが、落とし穴がある。`eager` を付けると**全記事の中身を 1 つの塊にまとめて読み込む**。記事が 2000 本になったら、トップページを開いただけで全部が転送される。

なので、**組み立ての前に索引を 1 回だけ作る**方式にした。

`scripts/build-index.mjs` が `src/routes/blog/` の下を歩き、各 `+page.md` の frontmatter を読んで、題名・日付・概要・タグだけを並べた `src/lib/index.generated.ts` を書き出す。

ページはこの索引だけを読む。記事の本文は、その記事を開いたときにだけ読み込まれる。これなら何本あっても一覧は軽い。

`package.json` に仕込んで、`npm run dev` と `npm run build` のたびに作り直すようにした。

```
"index": "node scripts/build-index.mjs",
"predev": "node scripts/build-index.mjs",
"prebuild": "node scripts/build-index.mjs",
```

`predev` と `prebuild` は npm の決まりで、`dev` と `build` の直前に自動で走る。

## タグを自動で付ける

タグを毎回手で書くのは続かない。本文に出てくる語から自動で付けるようにした。

索引を作るときに、本文を小文字にして、あらかじめ決めた語が含まれるかを見る。

```
k8s: ['kubernetes', 'k8s', 'kubectl', 'pod'],
docker: ['docker', 'dockerfile', 'コンテナ'],
```

`kubectl` と書いてあれば `k8s` のタグが付く。frontmatter に手で書いたタグがあれば、それと合わせる。

拾う語を増やしたいときは、この表に足すだけ。

## タグを「まとまり」として見せる

同じタグの記事を連載のように扱いたかったので、左の脇柱にタグを丸いアイコンで並べた。押すとそのタグの記事だけが出る。

アイコンは、タグ名から引く小さな表で決めている。表に無いタグは既定の印になる。

## 連載を書くとき

同じ話題を複数回に分けるときは、フォルダを入れ子にする。

```
src/routes/blog/k8s/01-pod/+page.md
src/routes/blog/k8s/02-deployment/+page.md
```

URL は `/blog/k8s/01-pod`。同じ話題が 1 箇所にまとまるので、記事が増えても散らからない。

日付を 1 日ずつずらし、題名に番号を入れておくと読む順が分かる。

## ここまでで

- `.md` を置けば記事になる
- 一覧とタグは自動
- 記事が増えても一覧は軽い
