ブログを置く場所として Cloudflare を選んだ。名前は聞いたことがあっても、何ができるのかは曖昧だったので整理する。

## もともとは CDN の会社

世界中にサーバを置き、利用者に一番近い場所から中身を返す仕組みを CDN という。Cloudflare はこれを本業として大きくなった。

CDN を挟むと 2 つ得がある。表示が速くなる。そして、元のサーバに直接アクセスが来なくなるので攻撃を受けにくくなる。

今はそこから広がり、世界中に置いたサーバの上で**自分のコードを動かせる**ようになっている。それが Workers。

## Workers

リクエストが来たときだけ実行される、小さなプログラムの置き場。

常時動くサーバを借りるのではないので、使っていない間は資源も料金も消費しない。無料枠が成り立つのはこのため。

制約もある。1 回のリクエストで使える CPU 時間に上限があり、Node.js の全機能が使えるわけでもない。重い処理には向かない。ブログの配信には十分すぎる。

## Pages

静的なサイト（HTML・CSS・画像）を置く仕組み。Git とつないでおけば push のたびに自動で公開される。

ただ Cloudflare は今 Workers を推している。Workers でも静的ファイルを配信できるようになり、分ける理由が薄くなった。

### どちらを選ぶか

| | Pages | Workers |
|---|---|---|
| 位置づけ | 先にあった方 | 今すすめられている方 |
| できること | 静的ファイル＋簡易な関数 | 静的ファイル＋全機能 |
| 料金 | 無料 | 無料 |

静的なページだけなら Pages で足りる。ただ、後から API を足したくなったとき、Pages だと別に Worker を立てて 2 つ管理することになる。最初から Workers なら 1 つで済む。

このブログは Workers にした。

## データを置く場所

Workers 自体はデータを持たない。保存が要るときは組み合わせる。

- **KV** — 鍵と値の単純な保存。設定やキャッシュ向き
- **D1** — SQLite の形のデータベース。記事や利用者のデータ向き
- **R2** — ファイルの置き場。画像や動画向き。転送料金がかからないのが特徴

このブログでは、まだどれも使っていない。画像は記事と同じフォルダに置いている。重くなってきたら R2 に移す。

## 無料枠の考え方

アカウント自体が無料で、使い始めるのにクレジットカードも要らない。

大事なのは、**カードを登録しなければ、無料枠を超えても課金されずに止まる**こと。意図しない請求にはならない。

具体的な数字は変わるので、使うときに公式の料金ページで確認した方がいい。

## アカウント ID と API トークン

自動で公開する仕組みを作るときに、この 2 つが要る。

**アカウント ID** は、ダッシュボードを開いたときの URL に入っている 32 桁の英数字。秘密ではない。

**API トークン** は、Cloudflare を操作する権限そのもの。作成直後の 1 回しか表示されず、閉じると二度と見られない。漏れると勝手に操作されるので、画面を人に送らないこと。

権限は必要な分だけに絞る。Workers に公開するだけなら Edit Cloudflare Workers で足りる。

## wrangler

Cloudflare を操作するコマンド。配信も、型定義の生成も、設定の確認もこれで行う。設定は `wrangler.jsonc` に書く。

自動公開では、このコマンドを GitHub Actions から呼ぶことになる。
