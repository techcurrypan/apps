技術ブログを一から作った記録を、再現できる形で残す。この連載を上から順にたどれば、同じものができる。

**この回が終わると**、何を作るのか・どういう仕組みで公開されるのか・費用はどうなるのかが分かる。手は動かさない。

## 作るもの

- Markdown で記事を書く
- 記事を 1 本足すと、一覧・タグ・検索・連載に自動で載る
- フォルダを分けると連載としてまとまる
- コードに色と行番号が付き、コピー釦が出る
- 目次が追従し、今読んでいる所が分かる
- 明るい配色と暗い配色を切り替えられる
- 検索・RSS・sitemap・アクセス解析が付く
- `git push` すると自動で検査され、通ったら公開される
- 記事が 2000 本になっても重くならない作りにする

## 作らないもの

- コメント欄・いいね・会員機能
- 記事を書くための管理画面
- 有料のサービスを使う機能

書くことに集中できる最小限だけを作る。

## 使う道具

| 道具 | 役割 |
|---|---|
| Node.js | 手元で動かすための土台 |
| SvelteKit | サイトを組み立てる枠組み |
| mdsvex | Markdown をページにする部品 |
| Prism | コードを色分けする部品 |
| GitHub | コードの置き場と、自動化の実行場所 |
| GitHub Actions | 検査と公開を自動で走らせる仕組み |
| Cloudflare Workers | 公開先 |
| wrangler | Cloudflare を操作するコマンド |

## 全体の流れ

```
手元で書く
  ↓  git push
GitHub
  ↓  GitHub Actions が動く
検査（型検査 → 組み立て）
  ↓  通ったときだけ
Cloudflare Workers へ配信
  ↓
公開 URL で見える
```

要点は、**検査を挟んでいる**こと。型の誤りや組み立ての失敗があれば、そこで止まる。壊れたものは公開されない。前の版がそのまま残る。

## 本当に無料か

無料になる根拠は 2 つある。

1 つ目。Cloudflare Workers は**リクエストが来たときだけ実行される**。常時動くサーバを借りるのではないので、読まれていない間は資源を消費しない。無料枠が成り立つのはこのため。

2 つ目。**クレジットカードを登録しない**。登録しなければ、無料枠を超えたときに課金されるのではなく、止まる。意図しない請求にならない。

GitHub Actions も、公開リポジトリなら実行時間が無料。

無料枠の具体的な数字と、課金が始まる条件は次の回で確認する。

## 必要な前提

- パソコン（Windows + PowerShell + VS Code で確認した。Mac でもほぼ同じ）
- GitHub のアカウント
- Cloudflare のアカウント（この連載で作る）

プログラムの経験はあった方が楽だが、コマンドをそのまま打てば進むように書いた。
