# 学習画面の水準

D-21 の具体の基準。**全項目を満たすまで段 10-R を終えない。段 9-2（街の上に重ねる板）も、この全項目を満たすまで終えない。**
手本は試作 `docs/prototype/learn/learn10.html`（利用者が 2026-11-15 に「とりあえず OK」と認めた物）。
**本番は、全項目で試作と同等以上にする。** 1 項目でも試作より劣れば不合格。試作に無い物（明暗・キーボード・全レッスンの中身など）は、本番で上回る所。

利用者が退けた物（同じ失敗をしない）：

| 退けた物 | 利用者の言葉 |
|---|---|
| 安い街の絵を学習画面に混ぜる | 「デザインがチープ」「中途半端な街デザインの学習画面は破棄」 |
| 参考サイトの配置・色・絵をそのまま写す | 「参考サイトそのまま」 |
| 何が何とつながるか分からない線、画面の中の小さなスクロール、拡大・移動できない図 | 「線でつないでおり関係性がわかりにくい」「画面内スクロールは操作性が悪い」「拡大縮小、移動が出来ない」 |
| 会話風・カード風に崩した画面 | 「物凄く劣化した」 |
| 学習画面の主役が 3D の街 | 「学習なのに街メインになっている」 |
| 荷物・OS・ログをタブで切り替える | 「タブより一画面で」 |
| 止まった絵で、何が起きたか動きで分からない | 「動的でわかりやすく」 |

---

## 0. 判定の決まり

- 各項目に **確かめ方** がある。数で測れる物は数で、見た目は「試作と本番を同じ場面・同じ画面の大きさで撮った 2 枚」で判定する
- 見た目の判定は、**作った本人ではなく別のエージェント**にさせる。渡すのは 2 枚の画像と項目の文だけ（作った経緯を渡さない）。
  返事は項目ごとに「本番 ≥ 試作」「本番 < 試作（理由）」。1 件でも「<」があれば直して撮り直す
- 判定の表は `docs/progress/phase-10.md` の「10-R 水準の表」に、項目 ID・確かめ方・結果・撮った画面の名前・判定した日で残す
- 撮影と測定は `scripts/look-learn.ts`（10-R で作る）。試作は `docs/prototype/learn/learn10.html` を手元の Chrome で開き、本番は公開 URL を開く。
  同じ台本で両方を動かし、`docs/progress/shots/phase-10-R/<場面>-proto.png` と `-prod.png` を残す
- 「比べる場面」（第 11 章）の全てを、1440×960 と 390×844 の両方で撮る

## 11. 比べる場面

試作と本番で、同じ台本を流して撮る。本番のレッスンは、同じ題を教えるレッスン（`curriculum.md` で探す）。
無い題は最も近いレッスンを選び、対応を `phase-10.md` の表に書く。試作の 4 本の中身（本物のバイト列・Git の ID・API の道・計算した損失）は
自分たちで作った物なので、同じ題の本番レッスンの `inside` に移してよい。

| 場面 | 試作 | 本番 | 見る項目 |
|---|---|---|---|
| C-1 概要 | `#net` 見る、最初 | net の同じ題 | LS-A・LS-D1〜D4・LS-T7 |
