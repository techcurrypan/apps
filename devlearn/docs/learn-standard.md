### 0.2 参考サイトから取る原理（2026-11-18 に開いて確かめた）

1. **図が画面の中心で一番大きい。** 左にコースの目次、右に語り、図はその間の全部を使う。拡大しなくても図の字が読める
2. **ステップに入ると、まず視点が関わる物へ滑らかに寄り、物が順に現れ、線が引かれ、札が付く。** 一度に全部は出ない
3. **流れている物は流れ続ける。** 選挙の票・ハートビート・要求の往復は、ステップに留まっている間も繰り返し線の上を進む。止まった絵の画面が無い
4. **図の上に指標の帯**（例：DNS 解決 20 ms・接続 60 ms・合計 155 ms、リーダー 1・任期 2）。ステップごとに数が増え、合計が積み上がる
5. **図の中に出来事の札**（例：選挙の 4 行の経過。今の行が光る）と、**機械ごとの状態の札**（例：「リーダー・任期 2」「B に投票済み」「まだ任期 1」）
6. **流れの種類の凡例**（要求・応答・ハンドシェイク／書き込み・投票依頼・ハートビート・古いリーダーの書き込み・失敗した要求）
7. **語りは 1 ステップ 2〜3 段落 ＋ 囲み 1 つ ＋「変わったこと」**（＋ 増えた・− 減った・〜 変わった）。ステップには種類の札（問題・テクニック・解決・トレードオフ・洞察）
8. **1 レッスンは 10〜12 ステップの物語**：問題 → 素朴な案の失敗 → 仕組み → 失敗のケース（止まっていたリーダー）→ 解決（フェンシングトークン）→ 代償（数で）→ 実際には（実在の製品の名前）→ まとめ
9. **学べることの一覧**が右下にあり、進むと ✓ が付く。下にステップの帯（番号と短い題が全部見える）
10. キー：← → でステップ、R でもう一度、Space で一時停止

### 0.3 判定

- **測りと撮影は公開 URL でだけ行う（D-24）。** 手元で組み立てた物の結果は、完成条件にも水準の表にも使わない。表には、測った時の公開の版（画面の一番下の「配信：」）を書く
- 各項目に**確かめ方**がある。数で測れる物は `scripts/look-learn.ts` とテストで測る。見た目と動きは、**作った本人ではない別のエージェント**に判定させる
- 別のエージェントに渡す物：項目の文、比べる場面（第 11 章）ごとの **本番の連続画像 8 枚**（ステップに入った瞬間から 0.25 秒ごと）と、同じ場面の試作 learn10 の連続画像、参考サイトの連続画像（0.4）。作った経緯は渡さない
- **判定者は 2 人**（互いの返事を見せない、別々のエージェント）。どちらも、場面ごとに**本番が参考サイトより劣る所を先に 3 つ以上挙げてから**、項目ごとに「≥」か「<（理由）」を返す。
  劣る所が 3 つ挙がらない場面は「どこを比べたか」を書かせる。**2 人のどちらかが「<」なら「<」**
- 動きの項目は「参考サイトと比べて、動きの量・滑らかさ・何が起きたかの分かりやすさが同等以上か」で判定させる
- 1 件でも「<」があれば直して撮り直す。結果は `docs/progress/phase-10.md` の「10-R 水準の表」に、項目 ID・確かめ方・結果・画像の名前・判定した日で残す
- 判定が全て「≥」になったら、利用者が後から見られるよう、公開 URL・見どころ・判定の結果を `phase-10.md` の「見てもらう材料」に残す（止まらない。D-20）。利用者が「利用者の指摘」に書いたことは、次の実行で今の作業より先に直す

### 0.4 参考サイトの撮り方

- `scripts/look-learn.ts --ref` が、手元の Chrome で参考サイトの決まった場面（第 11 章の R-1〜R-6）を開き、連続画像を `devlearn/.ref/`（**git に入れない**。`.gitignore` に入れる）に撮る
- 参考サイトの画面・文・絵をリポジトリ・配信物・記録に入れない。記録には「R-3 と比べて ≥」のように場面の名前だけを書く
- 参考サイトが開けない日は、判定を止めず、前に撮った `.ref/` を使う。`.ref/` も無ければ、第 0.2 の原理の文だけで判定させ、その旨を記録する

## 19. 4 つの使い方（見る・試す・やってみる・思い出す）

D-21 の 3 つに「試す」を足して 4 つにした（D-25）。上の帯の釦で行き来でき、最後の釦は次の使い方へ進む（例：見るの最後のステップの「次へ」は「試す：つまみを動かす」）。

## 20. 試作 learn11 から本番へ移す（段 10-P）

試作は 1 枚の HTML で、毎回の描画で SVG の文字列を作り直している。本番は Svelte 5 と TypeScript strict で、**作りを分けて同じ見た目と動きにする**。

| 試作（`learn11-src/core.js`） | 本番 |
|---|---|
| `SCN`・`sceneTo`・`scnPos`（構図の移り変わり） | `src/lib/learn/scene/layout.ts`：`(lesson, mode, step, prevStep, t) → 物ごとの位置・縮尺・透明度`。純粋な関数。単体テストで時間ごとの値を確かめる |
| `prism`・`rprism`・`rrectPts`・`localProj`・`hexPrism`・`cylinder`・`cube` | `src/lib/ui/scene/iso.ts`：等角の写し方と立体の面の計算（点の配列を返す）。描画しない。単体テスト |
| `drawObj`・`tok`・`pkt`・`pod`・`frameCard`・`objCard` | `src/lib/ui/scene/kit/<部品>.svelte`（第 17 章）。部品は位置・縮尺・状態・強調を受け取って SVG を描く |
| `tag`・`badge`・`card`・`anatomy`・`clock` | `src/lib/ui/scene/label/`。字の大きさは `UIK` を掛ける（16.3） |
| `UIK` の計算 | 図の枠の大きさを `ResizeObserver` で測り、`$derived` で求める |
| 繰り返し再生・一時停止・速さ・数え上げ | `src/lib/learn/player.ts`（D-21 の再生装置に足す） |
| 言葉（`terms`・`termBox`・`markTerms`・`showTip`） | `src/lib/learn/terms.ts` と `src/content/terms/<分野>.ts`（`explanation-standard.md` 第 10 章）。下線は本文を描く時に付ける（DOM を後から書き換えない） |
| レッスン 4 本（`tcp.js`・`k8s.js`・`mem.js`・`stat.js`） | レッスンのデータ（`explanation-standard.md` 第 2 章・2.3）。`Step.layout`・`Step.links`・`Step.draw` の代わりに、`Step.cues`（合図の時間軸）と見せ方の型ごとの描き方 |

- **性能**：1440×900 で 1 コマの計算と描画が 8 ms 以内（中くらいのノート PC。`look-learn.ts --perf` で 10 秒の平均）。毎コマ全てを作り直さず、変わった物だけを描き直す
- 色は `--dl-*` のトークン（明暗の両方）。字は `--dl-font`（外の書体を読まない）
- 試作の題の 4 本（TCP・Kubernetes・Python の名前と物・統計の平均のぶれ）は、本番の該当レッスン（見本 1・見本 2・`prg` の参照の題・`sta` の標本分布の題）の**下限**。本番はこれより深く（`explanation-standard.md` 2.3 の 10〜16 ステップ・本物のバイト列・出典）
