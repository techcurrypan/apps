## 1. 3 つの案

3 案とも、画面の種類は同じ 4 つにした（入口 / 地図 / レッスン / 仕事場。2.1）。違うのは、
1 つの画面の中に表し方をどう並べるかと、見た目の土台。

### 案 1　一枚の紙（一から作る）

```
┌───────────────────────────┐
│ 位置の帯（分野 › レッスン › 段）│
│ 進みの帯 ● ● ▶ ○ ○            │
├───────────────────────────┤
│ 舞台（図）                    │
├───────────────────────────┤
│ 文と具体値                    │
├───────────────────────────┤
│ 記録                          │
└───────────────────────────┘
│ 操作帯（画面の下に固定）       │
```

1. 画面の種類：入口 / 地図 / レッスン / 仕事場
2. 説明の画面：どの幅でも 1 列。上から図・文と値・記録。表し方は 3 つ
3. 図の見方：1 つ（物と物の関係の図）。時間の見方は記録が受け持つ
4. 位置：上の 2 本の帯
5. 操作：画面の下に固定した 1 本の帯
6. 実戦：同じ 1 列の中で、図が道具の状態に、操作帯が入力に替わる
7. ゲーム：別の画面（仕事場）。同じ 1 列の形
8. 見た目：色・文字・余白を一から決める
9. 携帯：そのまま 1 列

### 案 2　舞台と台本（Astryx を土台にする）

```
広い幅（960px 以上）
┌──────────────────────────────────────────┐
│ 位置の帯（分野 › レッスン › 段）   明暗 学習⇄仕事場 │
│ 段の帯  目的 前提 [解説] 例 実戦 確認 次             │
│ 進みの帯 1✓ 2✓ 3▶ 4○ 5○   3 / 5                   │
├─────────────────────────┬────────────────┤
│ 舞台（図）                │ 台本：文          │
│  前 → 動き 2/3 → 後        │  題・要約・本文・なぜ │
│                           ├────────────────┤
│                           │ 具体値の表        │
├─────────────────────────┤────────────────┤
│ 操作帯 ◀前 ↻もう一度 次▶ ⏵自動 速さ │ 記録（1〜n 行）    │
└─────────────────────────┴────────────────┘

狭い幅（960px 未満）
┌─────────────────┐
│ 位置の帯 / 段の帯     │
│ 進みの帯             │
│ 舞台                 │
│ 記録の最新 1 行       │
│ 台本：文・具体値      │
│ 記録（全部）          │
└─────────────────┘
│ 操作帯（下に固定）     │
```

1. 画面の種類：入口 / 地図 / レッスン / 仕事場
2. 説明の画面：左に舞台（図）と操作帯、右に台本（文・具体値・記録）。表し方は 3 つを同時に見せる
3. 図の見方：1 つ（物と物の関係の図）。時間の見方は記録が受け持ち、記録の最後の行と舞台の動きが同じ出来事を指す
4. 位置：位置の帯・段の帯・進みの帯の 3 本
5. 操作：舞台の真下の操作帯（狭い幅では下に固定）
6. 実戦：同じ枠のまま、舞台が道具の状態に、操作帯が入力に、台本が目的と返事に替わる
7. ゲーム：仕事場の画面。同じ枠で、舞台が依頼の板に、操作帯が手の一覧に、台本が理由と数値に替わる
8. 見た目：Astryx の theme-neutral のトークン（CSS 変数）を土台にし、日本語の文字・余白・動きは自分で決める
9. 携帯：1 列に畳み、舞台の下に記録の最新 1 行を置いて、図・文・記録が 1 画面に並ぶようにする

### 案 3　三つの窓（一から作る）

```
広い幅
┌────────────────────────────────┐
│ 位置の帯                        時の帯 1─2─3─4─5 │
├──────────┬──────────┬──────────┤
│ 図         │ 文と具体値  │ 記録        │
├──────────┴──────────┴──────────┤
│ 操作帯                                          │
└────────────────────────────────┘

狭い幅：窓を 1 つずつ切り替える（図 | 文 | 記録 の札）
```

1. 画面の種類：入口 / 地図 / レッスン / 仕事場
2. 説明の画面：等しい幅の 3 つの窓
3. 図の見方：1 つ
4. 位置：上の帯と、右上の時の帯
5. 操作：画面の下の帯
6. 実戦：図の窓が道具になる
7. ゲーム：3 つの窓を、依頼・手・記録に使う
8. 見た目：一から
9. 携帯：窓を札で切り替える

**選んだ案：案 2 舞台と台本。**

- D-1〜D-18 を全て満たすのは案 2 だけ
- 説明・実戦・ゲームが、同じ 4 つの領域（帯・舞台・操作帯・台本）の役割の入れ替えで収まる（U-9）。
  使う人は 1 つの形を覚えればよい
- 見た目の土台に Astryx のトークンを使うと、明暗 2 組の色が、文字と背景の差を保った値でそろう。
  一から 2 組を作って確かめるより、誤りが入りにくい

**落とした理由**

- 案 1：ノート PC の高さ（約 700px）では、図と記録が同時に画面に入らない（D-4）
- 案 3：狭い幅で窓を切り替える形が、表し方を同時に見せる原理に反する（D-4）。広い幅でも窓が狭い（D-12・D-18）

## 3. 画面ごとの構成

### 3.1 画面の種類

| 画面 | URL | 何のためか |
|---|---|---|
| 入口 | `/` | 続きから始める。地図・街へ行く |
| 地図 | `/map` | 分野とレッスンの一覧、修了の印、知識グラフ。どこからでも始められる（G-4） |
| レッスン | `/lesson/<id>` | 7 段（目的 / 前提 / 解説 / 例 / 実戦 / 確認 / 次）。解説はステップで進む |
| 街 | `/town` | ゲーム（港町づくり）。画面いっぱいの 3D の街に板を重ねる（第 10 章、D-15） |

配信の版（コミットの短い ID と組み立て日時）は、全ての画面の一番下に小さく出す（段 1 の画面の役目を引き継ぐ）。

### 3.2 共通の枠（4 つの領域）

| 領域 | 中身 |
|---|---|
| **帯** | 位置の帯（分野 › レッスン › 段、または 街 › 章 › 日目）、段の帯（レッスンだけ）、進みの帯 |
| **舞台** | 図。前の状態 → 動き → 後の状態を描く。下に「前 → 動き k/m → 後」の印と、記録の最新 1 行（段 6 で足した。広い幅でも、ノート PC の高さで記録が台本の下に隠れるため。原理 4） |
| **操作帯** | 舞台の真下。その場面で打てる操作の釦 |
| **台本** | 文（題・要約・本文・なぜ）、具体値の表、記録 |

| 場面 | 帯 | 舞台 | 操作帯 | 台本 |
|---|---|---|---|---|
| 解説 | 進み：ステップ n / 全体 | `stateAt(n).scene` | 前へ・もう一度・次へ・自動・速さ | 文：`text`、具体値：`facts`、記録：`log` |
| 例 | 進み：無し | 打った物と返った物を 1 行ずつ現す | 1 行進む・もう一度・全部 | 文：`example.intro` |
| 実戦 | 進み：打った回数 | 道具の状態（`tool` なら道具の図、`form` なら形ごとの図） | 入力（端末の 1 行、または形ごとの操作） | 文：目的と返事（`mistakes` の why と next）、具体値：出力、記録：打った物の履歴（巻き戻せる） |
| 確認 | 進み：確かめた数 / 全体 | 無し（台本だけ） | — | `check` の一覧と、確かめた印 |
| 目的・前提・次 | — | 無し | — | 目的の文、推奨前提・関連・次のレッスンへの道（ロックは無い） |
| 街の要望の板（10.4） | 依頼の帯：依頼主・期限・残りの勤務の時間 | 依頼の板：症状・疑い・候補 4 札 | 手の一覧（学んだ手 / いつでもの手、コマ、使えない理由） | 文：直近の手の理由、具体値：依頼主の満足度と線・資金、記録：出来事（選ぶと舞台で再生） |

### 3.3 舞台の動き（D-17・D-18）

1. ステップに入ると、まず**前の図**（`scene.before`）を `--dl-motion-hold` の間見せる
2. 次に `scene.motion` を**1 つずつ順に**再生する（原理 1）。1 つの長さは `--dl-motion-op` × 速さ
   - `appear`：その位置に薄く現れ、濃くなる
   - `move`：運ばれる物（`payload`）が、線に沿って `from` から `to` へ動く。瞬間移動させない
   - `change`：前の値に取り消し線が引かれ、後の値が現れる。両方が一瞬並ぶ
   - `highlight`：太い枠と「▶」の印
   - `vanish`：枠が点線になり、薄くなって消える
3. 最後に**後の図**（`scene.after`）で止まる
4. 舞台の下に「前 → 動き 2/3 → 後」の印。今どの段階かを文字で示す
5. **もう一度**（`R`）で、同じステップに留まったまま 1 から再生し直す。何度でも
6. 動きを減らす設定（`prefers-reduced-motion`）のときも、前 → 後は必ず見せる。
   `move` は点線の道と、行き先に現れる運ばれる物で示す（動きの長さを短くするだけで、省かない）

舞台は SVG で描く。物の置き場所は `appear` の `at`（列・行）を格子に当てる。格子 1 つは幅 160・高さ 96（SVG の単位）。
SVG の `viewBox` で舞台の幅に合わせて縮むので、携帯の幅でも全体が入る。
狭い幅（960px 未満）では、格子 1 つを幅 150 にし、物の中の値を「名前」と「値」の 2 行に分ける。携帯（舞台の幅 約 334px）に縮めても、値の字が 10px 以上になる（段 6 で決めた）。

### 3.4 状態と画面の対応

| 状態 | 見える物 |
|---|---|
| 解説のステップ n | 進みの帯：1〜n−1 に ✓、n に ▶、n+1 以降は ○ で題を出さない（原理 7）。舞台・文・具体値はステップ n、記録は 1〜n 行で n 行目に ▶ |
| 自動で再生中 | 操作帯の「自動」が「停止」に替わる。1 ステップの動きが終わると、`--dl-auto-wait` 待って次へ |
| 実戦で間違えた | 台本の文に「なぜ駄目か」と「次の一手」。印は ✕。舞台は打つ前と打った後を見せる |
| 実戦で合格 | 印は ✓。修了の記録を残す（L-6） |
| 街：要望の板を開いた | 舞台に候補 4 札。消えた札は斜線と「消」、確定した札は ✓ と太枠 |
| 街：手を打った | 舞台で `changes` を 1 つずつ再生（候補が消える → 疑いが減る → 数値が動く）。台本の文に理由 |
| 街：記録の 1 件を選んだ | その時点の状態を舞台に出し、その手の動きを再生。もう一度・前の手・次の手 |
| 街：章の失敗・合格 | 結果の板に評価。操作帯に「章の初めから」「選んだ時点から」「次の章へ」 |

## 4. 見た目の値（CSS 変数）

### 4.1 土台

Astryx theme-neutral 0.7.11 の `theme.css` を読み込み、使う所の要素に `data-astryx-theme="neutral"` を付ける。
devlearn の部品は Astryx の変数を直接使わず、次の `--dl-*` を使う。土台を替えるときは 4.2〜4.6 だけを直す。

### 4.2 色

色に持たせる意味は次だけ（原理 8）。分野ごとの色は作らない。

| 変数 | 値 | 意味 |
|---|---|---|
| `--dl-bg` | `var(--color-background-body)` | 地 |
| `--dl-surface` | `var(--color-background-card)` | 札・表の地 |
| `--dl-surface-raised` | `var(--color-background-surface)` | 舞台の地 |
| `--dl-text` | `var(--color-text-primary)` | 文字 |
| `--dl-text-muted` | `var(--color-text-secondary)` | 補いの文字 |
| `--dl-text-disabled` | `var(--color-text-disabled)` | 打てない操作 |
| `--dl-border` | `var(--color-border)` | 区切り |
| `--dl-border-strong` | `var(--color-border-emphasized)` | 物の枠 |
| `--dl-focus` | `var(--color-info)` | キーボードの焦点の輪 |
| `--dl-now` | `var(--color-text-info)` | 状態「今」（印 ▶） |
| `--dl-done` | `var(--color-text-success)` | 状態「済・正しい」（印 ✓） |
| `--dl-wrong` | `var(--color-text-error)` | 状態「誤り・減った」（印 ✕・−） |
| `--dl-warn` | `var(--color-text-warning)` | 状態「注意：期限が近い・疑いがある」（印 !） |
| `--dl-kind-1-fg` / `-bg` | `var(--color-text-blue)` / `var(--color-background-blue)` | 出来事の種類 1 |
| `--dl-kind-2-fg` / `-bg` | `var(--color-text-purple)` / `var(--color-background-purple)` | 出来事の種類 2 |
| `--dl-kind-3-fg` / `-bg` | `var(--color-text-teal)` / `var(--color-background-teal)` | 出来事の種類 3 |
| `--dl-kind-4-fg` / `-bg` | `var(--color-text-orange)` / `var(--color-background-orange)` | 出来事の種類 4 |
| `--dl-kind-5-fg` / `-bg` | `var(--color-text-gray)` / `var(--color-background-gray)` | 出来事の種類 5 以降 |
| `--dl-code-bg` | `var(--color-syntax-background)` | 具体値・端末の地 |

- 出来事の種類（`log.kind` と `move.kind`）は、レッスンの中で**初めて出た順**に種類 1, 2, … を割り当てる。
  同じ種類は舞台の運ばれる物と記録の行で同じ色。色に加えて、種類の名前を必ず文字で添える（D-14）
- 正誤・増減に使う緑と赤は、出来事の種類には使わない（意味が混ざらないように）

外部の書体は読み込まない（Astryx の `fonts.css` は外の書体配信を読むので使わない）。

### 4.5 動きの速さ

| 変数 | 値 | 根拠 |
|---|---|---|
| `--dl-motion-op` | `var(--duration-slow)`（700ms） | 1 つの動きを目で追える長さ。速さ ×1 のとき |
| `--dl-motion-hold` | `var(--duration-medium-max)`（400ms） | 前の図を見せてから動き出すまで。前の状態を目に入れる間 |
| `--dl-motion-ui` | `var(--duration-fast)`（125ms） | 釦や札の切り替え。舞台以外 |
| `--dl-auto-wait` | `1500ms` | 自動で進むとき、後の図を読む間 |

## 5. 携帯の幅での形（960px 未満）

- 1 列に畳む。上から：位置の帯・段の帯 → 進みの帯 → 舞台 → **記録の最新 1 行** → 台本の文・具体値 → 記録の全部
- 操作帯は画面の下に固定する。主な 3 つ（前へ・もう一度・次へ）を常に出し、自動・速さは「…」の中
- 舞台・文・記録の最新 1 行が、縦 640px の画面に収まるようにする（図と文と記録が同時に見える。原理 4）
- 表（具体値・記録）は枠の中で横に送れる。画面全体は横に送れない

## 8. 原理 1〜8 の対応表

| 原理 | どこで満たすか | 段 6 での確かめ方 |
|---|---|---|
| 1 一度に変わるのは 1 つ | 舞台は `motion` を 1 つずつ順に再生（3.3）。街の要望の板も `changes` を 1 つずつ。台本の文・具体値・記録はステップが替わるときに 1 度だけ替わる | 動きの途中で撮った画面に、動いている物が 1 つだけ |
| 2 変化が目に見える | `appear` は現れ、`move` は線に沿って動き、`change` は前と後の値が並び、`vanish` は点線で消える（3.3） | `move` の途中の画面で、運ばれる物が線の途中にある |
| 3 抽象の隣に具体値 | 台本で、文の真下に具体値の表。街では理由の文の真下に数値 | 全ステップで、文と具体値の表が隣り合う |
| 4 同じ瞬間を複数の表し方で | 舞台・台本の文・具体値・記録が、全て `stateAt(n)` の同じ `n` から描かれる。記録の最後の行に ▶。狭い幅でも舞台・記録の最新・文が 1 画面 | どのステップでも、文の題・具体値・記録の ▶ の行が同じ `n` |
| 5 今どこにいて、あとどれだけ | 位置の帯（分野 › レッスン › 段）、段の帯（7 段）、進みの帯（n / 全体、✓ ▶ ○）。街は 章・日目・時刻・残りの勤務の時間 | 各帯に今の位置と全体の数が出る |
| 6 速さを読み手が決め、戻れる | 既定は 1 つずつ。前へ・次へ・飛ぶ・自動・速さ・もう一度（操作帯と 6 章のキー）。街は記録から任意の時点へ戻れる | キーだけで全ての操作ができる |
| 7 進んだ所までしか見せない | 記録は 1〜n 行だけ。進みの帯の先のステップは題を出さない。実戦の答えは出さない | ステップ 2 で記録が 2 行、先のステップの題が無い |
| 8 色は意味にだけ | 色は 4 つの状態（今・済・誤り・注意）と出来事の種類だけ。分野に色を塗らない。全ての色に印か文字を添える | 灰色だけで撮った画面でも、印と文字で区別できる |

### 10.2 見た目

- 3D の街そのものは、時刻の光で見せるので明暗の切り替えの対象外（D-15、U-12）。街の中の色は試作のまま（地下の流れの分野の色は `game-design.md` 15.4）

### 10.4 要望の板（4 つの領域）

要望を開くと、街の上の中央に板を重ね、時計を止める（試作と同じ）。板の中は 3.2 の 4 つの領域の形にする（D-15）。

| 領域 | 中身 |
|---|---|
| 帯 | 依頼主（役割と建物）、症状の題、期限（あと何日）、残りの勤務の時間、閉じる（`Esc`） |
| 舞台 | 依頼主の言葉、候補 4 札（消えた札は斜線と「消」、確定した札は ✓ と太枠）、疑い（0〜2 の印）。手を打つと `changes` を 1 つずつ動きで見せる（3.4） |

### 10.6 キーボード（S-4）

文字を打つ欄に焦点があるときは、1 字の操作は効かない。

| キー | 何をする |
|---|---|
| `Space` | 一時停止 / 再開 |
| `1` `2` `3` | 速さ 1 / 2 / 3 |
| `W` `A` `S` `D`・矢印 | カメラを動かす（焦点が一覧・板の中に無いとき） |
| `Q` / `E` | カメラを回す（試作と同じ） |
| `+` / `-` | 近づく / 離れる |
| `N` | 明日の朝へ（次の 8:00 まで送る。確かめてから） |
| `R` | 最後に起きた変化をもう一度（建つ様子・流れ・浮かぶ数） |
| `Tab` / `Shift` + `Tab` | 上の帯 → 要望の一覧 → 街の上の印 → 右の板 → 道具 → 表示 の順に巡る |
| `Enter` / `Space` | 押す・選ぶ・要望を開く |
| `Esc` | 開いている板を閉じる（解説 → 要望の板 → 右の板 → 道具を「選ぶ」に戻す、の順） |
| `G` / `M` / `T` / `?` | 6 章と同じ（`G` は学習 ⇄ 街） |

- **道具をキーボードだけで使う**：住宅地・商業地・公園の道具を選ぶと、道具の案内に「使える空き区画」の一覧（区画の番号と場所の名前）が出る。`↑` `↓` で選ぶとカメラがその区画へ動き、`Enter` で指定する
- 道路の道具では、案内に「引き始められる点」の一覧が出る。選んだら矢印で向き、`[` `]` で長さを 10 m ずつ変え、試し引き（緑・赤と理由）を見て `Enter` で引く
- 建物を選ぶ：街の上の印は釦なので `Tab` で巡れる。印の無い建物は、`Tab` で街に焦点を置き `Enter` で、画面の真ん中の建物を選ぶ

### 10.7 動きを減らす設定（S-5）

- `prefers-reduced-motion` のときも、変化の前と後は必ず見せる
  - カメラの移動は飛ばさず、0.4 秒に縮める
  - 建物が建つ様子は、足場の絵（前）→ 建ち終えた絵（後）の 2 枚を、それぞれ `--dl-motion-hold` の間見せる
  - 浮かぶ数（+5 人・満足 ↑）は動かさずに、その場に 2 秒出す
  - 地下の流れの光の動きと赤い脈は止め、色と線の太さで示す
- 見た目だけの動き（車・人・船・波・旗）は、動きを減らす設定では速さを半分にする（止めると街が止まって見え、時間が流れているのが分からなくなるため）

### 10.8 WebGL2 が無い端末（T-7・P-4）

- 「この端末では 3D の街（WebGL2）を描けない。要望の一覧と、解き方の板で遊べる」と出す
- 上の帯（時刻・速さ・人口・資金・満足度・需要）、要望の一覧、要望の板、次の目標は、3D が無くても同じに出す。街づくりの道具は、10.6 の一覧から選ぶ形だけで使える
- 状態は 3D の描画と切り離してあるので（`game-design.md` 15.11）、遊びの規則は変わらない

### 10.9 読み込みと撮影

- 読み込みから街が見えるまで「街を描いています」と出す（P-6）
- URL の末尾が `#still` のときだけ、試作と同じ撮影の口を出す（`window.__game`・`window.__snap()`・`window.__frame(n, dt)`。`city-standard.md` 第 6 章）
