## 1. 3 つの案

### 案 A　よろず情報係

1. **題材** 架空の町の商店街で、ただ 1 人の情報係として働く。店から届く「困った」の依頼を、
   原因を突き止めて片付ける。店の信頼と、手元の資金を保つ
2. **1 回の行動** 依頼を 1 件選び、手を 1 つ打つ（調べる・直す・示す・聞く など）。
   手は「コマ」（勤務の時間）を使う。1 日は 8 コマ
3. **抵抗** 依頼の原因は、似た症状の候補が 4 つあって、どれか分からない。
   依頼主は思い込み（疑い）を持ち、根拠を見せるまで直すことを許さない。
   1 日の時間は限られ、期限を過ぎた依頼は信頼を減らす
4. **学びの効き方** 修了したレッスン 1 本ごとに、そのレッスンの道具や考え方を使う「手」が
   1 つ増える。学んだ手で調べると、原因を 1 コマで突き止め、その出力を根拠として依頼主に示せる
5. **学ばない道** いつでも使える手（様子を聞く・頼み込む・手探りで直す・再起動する・外に頼む）で、
   どの依頼も片付けられる。代償はコマ・信頼・資金が多くかかること
6. **進み方** 1 週 7 日で 1 章。章ごとに依頼を出す店（と分野）が変わる。
   週の終わりに信頼で評価し、合格すれば次の章が開く
7. **失敗** 1 日の終わりに信頼が 20 以下になると、その週は失敗。週の初め、または任意の日まで戻してやり直せる
8. **画面に要る物** 日とコマ、信頼と資金とその理由、依頼の一覧、選んだ依頼の候補 4 つ、使える手と使えない理由、
   出来事の記録と見返し

### 案 B　島つなぎ

1. **題材** 群島の島々を通信の網でつなぎ、島の間で荷（データ）を届ける
2. **1 回の行動** 部品（中継器・経路の表・暗号の箱など）を 1 つ置き、荷を流す
3. **抵抗** 島ごとに決まった時刻に嵐が来て、線が切れる。荷の量が日ごとに増える
4. **学びの効き方** レッスンを修了すると、そのレッスンの部品が置けるようになる
5. **学ばない道** 基本の部品（直結の線）だけで、遠回りしてつなぐ。代償は費用と遅れ
6. **進み方** つないだ島の数で新しい海域が開く
7. **失敗** 期限までに荷が届かない。海域の初めからやり直せる
8. **画面に要る物** 島と線の地図、荷の流れ、部品の在庫、嵐の予定

### 案 C　推理帳

1. **題材** 架空の町で起きる「データの事件」（帳簿の食い違い、消えた記録、怪しい通信）を解く
2. **1 回の行動** 手掛かりを 1 つ調べるか、推理を 1 つ述べる
3. **抵抗** 関係者が言い逃れをする。手掛かりは数が限られ、調べる回数に上限がある
4. **学びの効き方** 学んだ知識が「推理の札」になり、言い逃れを崩す根拠になる
5. **学ばない道** 聞き込みを重ねて、関係者の言葉の矛盾から迫る。代償は調べる回数
6. **進み方** 事件を解くと次の事件が開く。事件は決まった並び
7. **失敗** 回数を使い切る。事件の初めからやり直せる
8. **画面に要る物** 事件の要約、手掛かりの一覧、推理の札、関係者の言葉

## 2. 判定表

| 要件 | 案 A よろず情報係 | 案 B 島つなぎ | 案 C 推理帳 |
|---|---|---|---|
| B-1 学びが手になる | ○ 163 本全てに手がある（第 8 章）。手の出力が根拠として使われ、知識が判断に効く | × 網・セキュリティ・クラウドは部品になるが、統計・AI・法令・Git は部品にならず飾りになる | △ 全分野が札になり得るが、事件ごとに書き下ろしが要り、163 本全てに出番を作れない |
| B-2 学ばない道 | ○ いつでもの手 5 つで、どの依頼も片付く（6 章）。学ばずに全ての章を合格できることを 7.4 の模擬で確かめた | ○ 直結の線で遠回りできる | △ 聞き込みで迫れるが、回数に上限があり、詰む事件が出得る |

| B-4 乱数で決めない | ○ 依頼と原因は種と日からの決まった式（7.1） | ○ 嵐の予定を種で決める | ○ 事件は決まった並び |
| B-5 短い単位・状態が残る | ○ 1 日 = 最大 8 手で 2〜4 分。手の記録を保存 | △ 網が大きくなると 1 回の配置が重くなる | × 1 事件が長く、途中の推理の状態が複雑 |
| B-6 自作で描ける | ○ 札・記号・数値の帯で描ける | ○ 点と線の地図 | △ 関係者の絵が多く要る |
| B-7 写さない | ○ 依頼を候補で絞り込む仕組みは一般の原理。名前は全て一から | ○ | △ 推理もののお約束（証言を崩す型）が既存の作品に寄りやすい |
| B-8 変化を動きで見返す | ○ 1 手ごとの前と後を記録し、手の記録から任意の時点を作り直せる | ○ 荷の流れを再生できる | ○ 推理の流れを再生できる |

**選んだ案：A よろず情報係。**

- B-1〜B-8 を全て満たすのは A だけ
- 依頼の「候補を絞る → 根拠を示す → 直す」の流れは、どの分野にも同じ形で当てはまる。
  網の障害も、統計の読み違いも、AI の企画の穴も、「似た症状の候補のうちどれか」で表せる。
  だから 163 本全てに手を割り当てられる
- 学んだ手の出力（`dig` の結果、検定の値）が、そのまま依頼主に示す根拠になる。知識が飾りでなく判断の材料になる

**落とした理由**

- 案 B：統計・AI・法令・Git の学びが、島をつなぐ部品として出番を持てない（B-1 で落ちる）
- 案 C：事件ごとの書き下ろしが重く、1 回の遊びが長い（B-5）。関係者の絵が多い（B-6）。
  学ばない道が回数の上限で詰み得る（B-2）

## 3. 選んだ案の全体

- 町：架空の商店街。名前は付けない（「町」「商店街」と呼ぶ）
- 依頼主は役割で呼ぶ：パン屋の店主 / 診療所の受付 / 運送屋の配車係 / 組合の事務長。人名は付けない
- 章は 4 つ。章ごとに依頼を出す店と、主に効く分野が変わる

| 章 | 依頼主 | 主に効く分野 | 依頼の症状（第 9 章） |
|---|---|---|---|
| 第 1 週 | パン屋の店主 | `prg` `lnx` `net` `git` | G01〜G11 |
| 第 2 週 | 診療所の受付 | `sec` `db` `ai`（法令・倫理） | G12〜G17 |
| 第 3 週 | 運送屋の配車係 | `sta` `ai` | G18〜G27 |
| 第 4 週 | 組合の事務長 | `ctr` `cld` `ci` | G28〜G34 |

- 4 章の後は「自由の週」：全ての症状（G01〜G34）から依頼が届く（7.1 の `G_w` を全ての症状にする）。種を変えて何度でも遊べる
- どの章も、前の章を合格すれば開く。**学習の進みでは開かない**（B-2）

## 4. 1 回の行動と手

### 4.1 依頼

依頼は、症状 1 つと、原因の候補 4 つを持つ。候補のうち 1 つが本当の原因。
依頼主は疑い（0〜2）を持ち、疑いが 0 になるまで「直す」を許さない。

| 依頼の状態 | 意味 |
|---|---|
| 受付中 | 届いて、まだ片付いていない |
| 確定 | 本当の原因が分かった（他の候補が全て消えたか、調べて当たった） |
| 解決 | 直した |
| 一時解決 | 再起動でしのいだ。2 日後に同じ原因で再び届く |
| 外に頼んだ | 次の日の朝に片付く |
| 期限切れ | 期限までに片付かなかった |

### 4.2 手

| 手 | 種類 | コマ | 使える条件 | 効き目 |
|---|---|---|---|---|
| 学んだ手で**調べる** | 学び | 1 | その手が調べられる原因が、候補に 1 つ以上ある。確定していない | 調べられる候補のうち、本当の原因があれば**確定**。無ければ、調べた候補を全て消す。道具の出力を根拠として残す |
| 学んだ手で**直す** | 学び | 1 | 確定している。その手が本当の原因を直せる。疑いが 0 | **解決** |
| **示す** | 学び | 1 | 学んだ手で調べて確定した（根拠がある）。疑いが 1 以上 | 疑いを 0 にする |
| **様子を聞く** | いつでも | 1 | 確定していない | 候補の並びで最初の、本当でない候補を 1 つ消す |
| **頼み込む** | いつでも | 1 | 疑いが 1 以上 | 疑いを 1 下げる。信頼 −1 |
| **手探りで直す** | いつでも | 2 | 確定している。疑いが 0 | **解決** |
| **再起動する** | いつでも | 1 | 疑いが 0（店を止めるので了承が要る） | 本当の原因が「再起動で一時的に直る」物（第 9 章の印）なら**一時解決**。報酬は半分。2 日後に同じ原因で再び届き、疑いは 1 増える。そうでなければ、印の付いた候補が消える |
| **外に頼む** | いつでも | 0 | 資金が費用以上ある | **外に頼んだ**。資金 − 費用。次の日の朝に片付く |

- 再起動は、原因が確定していなくても打てる。原因が印の付いた物でなければ「何も変わらなかった」と
  理由を示す。試した結果は手掛かりになり、印の付いた候補が消える
- 使えない手は、使えない理由を 1 行で示す（例：「疑いが 1 残っている。示すか頼み込む」）
- 学んだ手で調べたとき、その手のレッスンの道具の出力（段 7 の模擬と同じ形）を出す。
  依頼主に示す根拠は、この出力と、平易な一言の読み方

### 4.3 学んだ手はどこから来るか

- 修了したレッスン 1 本につき、そのレッスンの手が 1 つ使えるようになる（第 8 章の表）
- 修了の記録はブラウザ内（L-6）。ゲームはこの記録を読むだけで、書き換えない
- 依頼を選ぶと、「この依頼の候補を調べられる手」と、その手を教えるレッスンが分かる。
  レッスンへは行けるが、行かなくても続けられる（段 9）

## 5. 抵抗

| 抵抗 | なぜ抵抗するか | 越え方 |
|---|---|---|
| 候補が 4 つある | 症状が同じでも原因は違う。現場で一番多い難しさをそのまま置いた | 学んだ手で調べる（1 コマで当たるか、まとめて消える）／様子を聞く（1 コマで 1 つ消える） |
| 依頼主の疑い | 店主は「機械が壊れた」「うちは狙われない」と思い込んでいる。根拠なしに止めたり費用をかけたりを許さない | 示す（根拠が要る）／頼み込む（信頼を削る） |
| 1 日 8 コマ | 1 人の勤務は限られる | 学んだ手は少ないコマで済む |
| 期限 | 店は待てない | 早く片付ける／外に頼む |

## 6. 学ばない道と代償

| 学ばない道 | 代わりにする手 | 代償 |
|---|---|---|
| 原因を突き止める | 様子を聞く × 3 | 3 コマ（学んだ手なら 1〜2 コマ） |
| 疑いを解く | 頼み込む × 疑い | 1 コマと信頼 −1 を疑いの数だけ（示すなら 1 コマで信頼は減らない） |
| 直す | 手探りで直す | 2 コマ（学んだ手なら 1 コマ） |
| しのぐ | 再起動する | 報酬が半分。2 日後に再び届き、信頼 −3、疑いが増える |
| 手が回らない依頼 | 外に頼む | 報酬より 1.5 倍高い費用 |

どの依頼も「様子を聞く × 3 → 頼み込む × 疑い → 手探りで直す」で必ず片付く（候補 4 つのうち
本当でない 3 つが消えれば確定するため）。だから学ばずに進める道は、どの依頼にも必ずある（B-2）。

## 7. 数と式

### 7.1 依頼の届き方（種と日から決まる。乱数を使わない）

- 章 `w` の症状の一覧を `G_w`（並びは第 9 章の順）、その数を `N_w` とする
- 日 `d`（1〜7）の `k` 件目（0〜2）の通し番号 `i = 3(d − 1) + k`（0〜20）
- 症状：`G_w[(s + i) mod N_w]`。`s` は種（0 以上の整数）
- 本当の原因：その症状の原因の一覧（大きさ `m`）の `(s + 11i) mod m` 番目
- 候補 4 つ：本当の原因から一覧の並びで続く 4 つ（末尾の次は先頭）を取り、一覧の並びに並べ直す
- 様子を聞くが消す順：候補の並びで前から

| 数 | 値 | 根拠 |
|---|---|---|
| 1 日の新しい依頼 | 3 件 | 学んだ手を使えば 1 件あたり約 2.7 コマ（7.4）で、3 件 ≈ 8 コマに収まる。学ばないと 1 件あたり約 5.5 コマで、3 件のうち 1〜2 件しか片付かない。差がちょうど「学ぶ得」になる |
| 候補の数 | 4 | 様子を聞くで確定するまで 3 コマ、学んだ手なら 1〜2 コマ。差が 1〜2 コマで、1 日 8 コマの中で効きが分かる。4 枚なら携帯の幅でも並べられる |
| 原因の並びの歩み `11` | 11 | 素数で、症状の原因の数（4〜7）のどれとも共通の約数を持たない。日が進むと本当の原因が一覧の全てを巡る |
| 種の既定 | 1 | 時刻や乱数から作らない。使う人が「別の種で遊ぶ」を選ぶと 1 ずつ増える |
| 期限 | 届いた日を含めて 3 日 | 1 日で 3 件を片付けきれなくても、2 日分の余裕で取り返せる。4 日以上にすると積み残しが溜まり、画面の一覧が長くなる |
| 再発までの日 | 2 日 | 期限（3 日）より短く、同じ週のうちに再び届いて代償が見える |

### 7.2 コマ

| 数 | 値 | 根拠 |
|---|---|---|
| 1 日のコマ | 8 | 1 コマを勤務の 1 時間に見立てた。1 手 15〜30 秒で考えて、1 日 2〜4 分（B-5） |
| 学んだ手（調べる・直す・示す） | 1 | 道具の使い方を知っていれば 1 時間で済む、という見立て |
| 様子を聞く・頼み込む・再起動する | 1 | 人と話す・機械を立ち上げ直すのは 1 時間 |
| 手探りで直す | 2 | 原因が分かっていても、直し方を知らなければ倍かかる、という見立て。学んだ直す手との差 1 コマが、直し方を学ぶ得 |
| 外に頼む | 0 | 電話 1 本で済む。代わりに資金を使う |

### 7.3 信頼と資金

| 数 | 値 | 根拠 |
|---|---|---|
| 信頼の始まり | 50（0〜100） | 真ん中から始め、上にも下にも動けるようにした |
| 解決 | +3 | 1 日 3 件を全て片付けると +9〜+12。7 日で上限 100 に届く速さ |
| 届いた日のうちに解決 | さらに +1 | 早さを褒める。積み残しとの差を作る |
| 外に頼んで片付いた | +1 | 片付いたことは店に喜ばれるが、自分で直したほどではない |
| 一時解決 | +1 | 店はひとまず動くので喜ぶ |
| 再発して届いた | −3 | 一時しのぎの付け。一時解決の +1 と合わせて −2 になり、しのぐのは損だと分かる |
| 期限切れ | −5 | 解決の +3〜+4 より重い。放っておくのは、片付けないより悪い |
| 頼み込む | −1 | 信頼を少し削って押し通す |
| 失敗の線 | 1 日の終わりに 20 以下 | 始まりから 30 減ると失敗。期限切れ 6 件分で、取り返しがつかないほど放った場合だけ |
| 合格の線 | 7 日目の終わりに 40 以上 | 始まりから 10 までの目減りは許す |
| 良 / 優 | 70 以上 / 90 以上 | 学ばない道でも「良」に届き得て、学んだ手を使うと「優」に届く（7.4） |
| 資金の始まり | 60 | 初日から外に頼む（軽い依頼 2 件、重い依頼 1 件）ができる |
| 報酬 | 重さ 1 は 20、重さ 2 は 40 | 重い依頼は候補が多い症状（第 9 章）に付け、2 倍にした |
| 一時解決の報酬 | 報酬の半分 | 片付けていないので満額は貰えない |
| 外に頼む費用 | 報酬の 1.5 倍（30 / 60） | 外に頼むたびに 10〜20 減る。手が回らないときの逃げ道で、頼り切ると資金が尽きる |

資金が尽きても失敗ではない。外に頼む手が使えなくなるだけ。

### 7.4 見積もり（学ばない道でも通せること）

1 件にかかるコマ（疑いの平均は、第 9 章の表から数えて 0.79）：

| 遊び方 | 原因を突き止める | 疑い | 直す | 計 |
|---|---|---|---|---|
| 学ばない | 様子を聞く 3 | 頼み込む 0.8 | 手探り 2 | 約 5.8 |
| 学んだ | 調べる 1〜2 | 示す（疑いがあるときだけ 1） | 1 | 約 2.5〜3.5 |

この文書の規則（4.2・7.1〜7.3・11 章）どおりに動く使い捨ての模擬（Python。リポジトリには入れていない）で、
4 章 × 種 5 つ（0・1・2・3・7）を、決まった遊び方で流した。
遊び方は「期限の近い依頼から、打てる手のうち学んだ手を先に打つ。その日が期限の残りは、資金があれば外に頼む」。

| 遊び方 | 7 日目の信頼（20 通り） | 結果 |
|---|---|---|
| 学ばない | 68〜79 | 全て合格。多くは「良」。資金は 0〜50 まで減る |
| その章の分野のレッスンを半分修了 | 80〜99 | 全て「良」以上。資金は 310〜580 |
| その章の分野のレッスンを全て修了 | 100 | 全て「優」。資金は 520〜740 |

- 学ばなくても、どの章のどの種でも合格に届く（B-2）

### 7.5 理由の文（B-3）

数が動くたびに、次の形の理由を 1 件残す。全て平易な言葉で、何によって・いくつ動いたかを書く。

- 「信頼 +4：パン屋の『注文の頁が開かない』を、届いた日のうちに直した（+3、早さ +1）」

## 10. 状態の型

モデル層は DOM を知らない。画面は、状態と出来事の記録だけから描く。

```ts
type LessonId = string;   // 'net-004' など
type CauseId = string;    // 'c-dns' など
type GroupId = string;    // 'G03' など

// 決まったデータ（第 8・9 章の表をそのままデータにした物）
type Cause = { id: CauseId; label: string; restartable: boolean };
type Group = {
  id: GroupId;
  week: 1 | 2 | 3 | 4;
  client: string;
  symptom: string;
  weight: 1 | 2;
  doubt: 0 | 1 | 2;
  causes: CauseId[];      // 4〜7。この並びで候補を取る
};
type LearnedMove = {
  id: string;             // レッスン ID と同じ
  lesson: LessonId;
  name: string;
  tests: CauseId[];
  fixes: CauseId[];
};

// 遊びの状態
type RequestStatus = 'open' | 'solved' | 'temp' | 'outsourced' | 'expired';
type Request = {
  id: string;             // 'w1-d2-k0' や再発の 'w1-d4-r0'
  group: GroupId;
  arrived: number;        // 届いた日
  due: number;            // 期限の日（この日の終わりまで）
  candidates: CauseId[];  // 4 つ。一覧の並び
  truth: CauseId;
  ruledOut: CauseId[];    // 消えた候補
  confirmed: boolean;
  evidence: string | null;// 学んだ手で確定したときの根拠（道具の出力の要約）
  doubt: number;
  status: RequestStatus;
  doneDay: number | null; // 片付いた日
};

type GameState = {
  version: 1;
  seed: number;
  week: 1 | 2 | 3 | 4 | 'free';
  day: number;            // 1〜7
  slots: number;          // 残りのコマ
  trust: number;
  money: number;
  requests: Request[];
  result: 'playing' | 'failed' | 'passed';
  grade: '合格' | '良' | '優' | null;
};

type Action =
  | { type: 'test' | 'fix'; move: string; request: string }
  | { type: 'show' | 'ask' | 'plead' | 'grope' | 'restart' | 'outsource'; request: string }
  | { type: 'endDay' };

// 1 つの手で起きたこと。振り返りの再生はこれだけで描ける
type Change =
  | { what: 'trust' | 'money' | 'slots' | 'doubt'; before: number; after: number; why: string }
  | { what: 'ruledOut'; request: string; causes: CauseId[]; why: string }
  | { what: 'status'; request: string; before: RequestStatus | 'confirmed-no'; after: RequestStatus | 'confirmed'; why: string }
  | { what: 'arrive' | 'expire'; request: string; why: string };

type GameEvent = { day: number; seq: number; action: Action | { type: 'morning' }; changes: Change[] };

// 保存する物（B-5）。状態は保存しない。手の記録から毎回作り直す
type Save = { version: 1; seed: number; week: GameState['week']; actions: Action[] };

// 純粋な関数
// start(seed, week): GameState                      … 1 日目の朝まで
// apply(state, action, learned: Set<LessonId>): { state: GameState; event: GameEvent }
// replay(save): { states: GameState[]; events: GameEvent[] }   … 任意の時点を作り直す
// usable(state, request, learned): { move: string; ok: boolean; why: string }[]
```

- 状態を決める処理に `Math.random` と `Date.now` を使わない（B-4。段 8 でテストで確かめる）
- 振り返りでは、記録した手を学んだ手の可否を問わずに当て直す（記録した時点で可だったため）。
  だから後で修了の記録が変わっても、過去は変わらない
- 任意の時点の画面は `replay` の `states[k]` だけから描く。巻き戻しは「手の記録を k 件で切る」こと

## 11. 1 日の処理の順序

1. **朝**
   1. 外に頼んだ依頼を「解決」にする（信頼 +1）
   2. 期限（`due`）が前の日だった受付中の依頼を「期限切れ」にする（信頼 −5 ずつ）
   3. 再発の依頼が届く（その日に届く物。信頼 −3 ずつ。疑いは元の依頼の始まり + 1、上限 2。
      一度しのいで再び壊れたので、依頼主はより疑う。上限は疑いの幅 0〜2 に合わせた）
   4. 新しい依頼が 3 件届く（7.1）
   5. コマを 8 にする
2. **昼**：使う人が手を 1 つずつ打つ。各手は 4.2 の条件を確かめ、コマを引き、効き目を当てる。
   コマが足りない手は打てない
3. **夜**（「1 日を終える」を選んだとき）
   1. 信頼が 20 以下なら、その週は失敗
   2. 7 日目なら週の評価（7.3 の線）。合格以上で次の章が開く。
      この時点で受付中の依頼は数えない（期限の前に週が終わった物を罰しない。次の週へも持ち越さない）
   3. それ以外は次の日の朝へ

朝の順（片付く → 期限切れ → 再発 → 新規）の根拠：先に片付いた物を除くと、期限切れの数え違いが起きない。
新規を最後に置くと、その日の一覧の末尾に新しい物が並ぶ。

## 12. 失敗とやり直し

- 失敗：1 日の終わりに信頼 20 以下
- やり直し：週の初めから、または手の記録の任意の時点から。どちらも `replay` で作り直す
- 合格した週も、種を変えて遊び直せる（評価は良い方を残す）

## 13. 変化を見せる・見返す（B-8）

- 1 手ごとに `GameEvent` を残す。`changes` は前と後の値を持つ
- 画面は、手を打つたびに `changes` を順に動きで見せる（候補が消える、疑いが減る、信頼の数が動く）
- 記録の 1 件を選ぶと、その手の動きを何度でも再生し直せる。前後の手へ進む・戻るもできる
- 巻き戻して別の手を打つと、その時点から新しい記録が始まる（前の続きは捨てる。捨てる前に確かめる）

### 15.1 時間の刻み

- 状態の時刻は **ゲーム内の分**（整数）。`minute = 0` は 1 日目の 0:00。描画のコマ（実時間）とは分ける
- 状態を進める関数は `tick(state, toMinute)` だけ。1 分ずつ進め、時（:00）をまたぐたびに 15.5 の毎時の処理を、
  8:00・17:00 に 15.2 の朝・締めを行う。描画は実時間を足し込んで整数の分にし、`tick` を呼ぶだけ
- 速さは「1 実時間秒あたりに進めるゲーム内の分」だけを変える。状態の規則は速さを知らない

| 速さ | 1 秒あたり | 1 日（24 時間）の長さ | 根拠 |
|---|---|---|---|
| 一時停止 | 0 分 | — | 要望の板を開くと止まる（試作と同じ）。考える間に勤務の時間が減らない |
| 1 | 10 分 | 2 分 24 秒 | 1 日が 2〜4 分（B-5）。勤務の 8 時間が 48 秒で、街の動きを目で追える。試作と同じ |
| 2 | 30 分 | 48 秒 | 夜を早く送る。試作と同じ |
| 3 | 80 分 | 18 秒 | 区画が育つのを待つ。1 時間が 0.75 秒で、建つ様子（1 時間）がまだ見える。試作と同じ |

- 手の記録は `{ at: 分, action }` の並び。`replay` は「`at` まで `tick` → `apply`」を順に繰り返す。同じ種と同じ並びで同じ状態になる（B-4、要件の T-8）
- 一時停止や速さの切り替えは状態を変えないので、記録に入れない

| 17:00〜翌 8:00 | 夜。街は動き、区画は育ち、収支は入るが、コマを使う手は打てない | 夜の光（V-5）を見せる時間。速さ 3 で 11 秒で送れる |

- 残りのコマ = `floor((17:00 − max(今, 9:00)) / 60)`、0〜8。9:00 より前に手を打つと、9:00 から始めたことにする
- コマを使う手は、`今 + コマ × 60 ≤ 17:00` のときだけ打てる。打てないときは「今日の勤務は残り 0 時間。明日 9:00 から」と理由を出す
- コマを使わない手（外に頼む、15.4 の「つなぐだけ」の直す）と街づくりの操作は、いつでも打てる（電話 1 本、資金だけで済むため）
- 勤務の時間に時計を流すと、コマも減る（眺めている間に、その日の勤務は過ぎる）。要望の板を開くと止まるので、考える間には減らない
- 「明日の朝へ」（`E`）で、次の 8:00 まで時計を送れる（`tick` の飛ばし。記録には入らない）
- 始まりは 1 日目の 8:00、朝の処理を終えた所（要望 3 件が届いた所）

### 15.5 街の数

**依頼主の満足度**（章の評価に使う。段 4 の信頼をそのまま読み替えた）

- 章の初めに 50。0〜100。動く値は段 4 の 7.3 と同じ（解決 +3、届いた日のうち +1、外に頼んで片付いた +1、一時解決 +1、再発 −3、期限切れ −5、頼み込む −1）
- 根拠：段 4 の 7.4 の見積もりと線（失敗 20 以下、合格 40、良 70、優 90）を、そのまま使えるようにするため。
  建物の位置から評価を出すと、街の形を少し直しただけで合否が動いてしまう

**建物ごとの満足度** `s_b`（0〜100）と**町の満足度**

| 項 | 式 | 根拠 |
|---|---|---|
| 基礎 | `55 + (mix32(seed, b.id) mod 11)`（55〜65） | 平均 60 で、満足度の表示が黄の帯に入る。±5 のむらで、満足度の表示が一色にならない。試作は 55〜80 を擬似乱数で引いていた。式に直して幅を狭めた |
| 公園 | 60 m 以内の公園 1 つにつき +6、+12 まで | 試作と同じ。2 つまでにして、公園を並べるだけで 100 に届かないようにした |
| 要望 | 依頼主の建物から 100 m 以内の建物に、依頼主の満足度と同じ動きを足す | 試作の街で数えると、100 m 以内は依頼主 1 人あたり 16〜48 棟（隣の区画まで）。60 m では 3〜20 棟で変化が見えにくく、120 m では別の依頼主の周りと重なり過ぎる（2026-11-11 に試作の街で数えた） |
| 建物 | `s_b = clamp(基礎 + 公園 + 要望, 0, 100)` | — |
| 町の満足度 | 見えている建物（建つ途中・隠れた物を除く）の `s_b` の平均。画面には整数で出す | 試作と同じく建物ごとの平均。人数で重みを付けると、事務所の多い所だけで決まってしまう |

`mix32` は 32 ビットの整数の混ぜ合わせ（掛け算と xor と桁送り）。`Math.sin` を使う試作の `hash2` は、ブラウザによって最後の桁が違い得るので、状態には使わない。

**人口と働く場所**

- 人口 = 建ち終えた建物の住む人の合計。働く場所 = 建ち終えた建物の働く場所の合計。始まりは試作の街のまま（人口 2,358、働く場所 3,441。2026-11-11 に試作の `gen.js` を Node で動かして数えた）
- 区画に建つ家は住む人 5、店は住む人 2・働く場所 6（試作と同じ。店の働く場所は試作の街の店と同じ）

**需要**（住・商・職。5〜95）

| 需要 | 式 | 根拠 |
|---|---|---|
| 住 | `50 + 1.2 × (町の満足度 − 60) + 5 × 建てた店 − 3 × 建てた家` | 試作の式。満足度が 10 上がると 12 増える。家が建つたびに 3 ずつ満たされ、およそ 10 棟で落ち着く |
| 商 | `30 + 4 × 建てた家 − 9 × 建てた店 + floor(人口 / 300)` | 試作の式。家 2〜3 棟ごとに店 1 つ分の需要が生まれる |
| 職 | `40 + floor(人口 / 300) − floor(働く場所 / 200)` | 試作の式。店を建てると下がる。始まりは 31 |

**資金**

| 数 | 値 | 根拠 |
|---|---|---|
| 始まり | 600 | 段 4 の 60 の 10 倍。値を 10 倍にしたのは、区画の指定 20・公園 80 と同じ桁にするため |
| 報酬 | 重さ 1 は 200、重さ 2 は 400 | 段 4 の 20 / 40 の 10 倍 |
| 一時解決の報酬 | 報酬の半分 | 段 4 と同じ |
| 外に頼む費用 | 300 / 600 | 段 4 の 30 / 60 の 10 倍（報酬の 1.5 倍） |
| 毎時の収支 | `floor(人口 × 0.02) + floor(働く場所 × 0.01) − 70 − floor(道路の長さ(m) × 8 / 1000)` | 税の率は試作（0.018・0.012）を丸めた。維持費 70 は、始まりの町の収支を 1 時間 +11（1 日 +264）にするため。1 日の税が、軽い依頼 1 件を外に頼む費用（300）に届かないので、税だけで外に頼み続けることはできない。道路の維持費は試作と同じ 1 km あたり 8 |
| 章の合格の報酬 | 合格 300・良 600・優 900 | 軽い依頼を外に頼む 1〜3 件分。次の章で道や区画に使える |
| 町の格が上がった報酬 | 300 | 同じ |

- 試作にあった「業者に任せた仕組みの使用料（毎時）」は入れない。4 章を学ばずに通すと外に頼むのは 25 件ほどになり、毎時の使用料が税を上回って資金が減り続けるため。外に頼む代償は、段 4 と同じく 1.5 倍の費用と、使い回せない箱にする
- 資金は毎時の収支で 0 を下回り得る（赤字。数を「−」で出す）。資金を使う操作は、資金が費用以上のときだけ打てる
- 理由の文（B-3）は段 4 の 7.5 の形に、街の物を足す。例：「資金 +11：1 時間の収支（住民税 47、店と会社の税 34、維持費 −70）」
  「資金 −20：空き区画を住宅地に指定した」「人口 +5：住宅地に家が建ち終えた（住の需要 62）」「満足度 +6：60 m 以内に公園ができた」

**毎時の処理の順**（`:00` ごと）：収支を足す → 建ち終えた建物を数に入れる → 指定した区画が育つ（15.6）。
根拠：収支は前の 1 時間の人口で数える。建ち始めた物は 60 分後の時から数に入る（同じ時に増えて数え違うのを避ける）。

### 15.7 目標と一区切り

- **一区切りは章**（7 日）。段 4 の週の評価を、7 日目の 17:00 の締めに行う。線は段 4 と同じ（依頼主の満足度が締めで 20 以下なら失敗、7 日目の締めで 40 以上なら合格、70 以上で良、90 以上で優）

  **街（建物・区画・道路・資金・建物ごとの満足度・人口）は章をまたいで続く**
- 失敗したとき・合格しなかったときは、時計が止まり、「章の初めから」「選んだ時点から」を出す。どちらも手の記録を切って `replay` で作り直す（段 4 の 12 章）。
  その章の間に引いた道や指定した区画も、切った所より後の物は無くなる（街も同じ記録から作るため）
- **町の格**（人口で決まる。目標の並び）

|---|---|---|
| 小さな港町 | 始まり（2,358） | — |
| 港町 | 2,450 | 家 19 棟。始まりの 9 区画と、道 1 本の沿いの区画で届く |
| にぎわう港町 | 2,600 | 家 49 棟。道 3〜4 本 |
| 港の市 | 2,800 | 家 89 棟。章を 2〜3 つ通して育てる大きさ |

- 何もしないと、期限切れ（−5）が 4 日目の朝から 3 件ずつ重なり、5 日目に 20 を割る。失敗の線は、放ったときだけ当たる
- 町の満足度の列は、基礎を全ての建物で 60 として数えた（`mix32` のむらは平均 60 で、平均を動かさない）
- 8-2d で、同じ遊び方を単体テストにし、この表と同じ結果になることを確かめる（A-8・A-11）

### 15.9 保存

- 保存するのは**種と、手の記録と、時計の今**だけ：`{ version: 1, seed, now, actions: { at, action }[] }`。ブラウザ内（`localStorage`）に置く（段 4 の 10 章、要件の L-6）
- 街づくりの操作（指定・公園・道路・取り壊し）も `action` に入る。区画・道・建物は記録から作り直す（T-8）
- 修了したレッスンの集まりは保存しない（ゲームは学習の記録を読むだけ。段 4 の 4.3）。当て直しでは、記録した手を学んだ手の可否を問わずに当てる（段 4 の 10 章）
- 街の形（地形・始まりの建物・区画・道）は `gen` の決まった出力で、保存しない。状態は、その建物の番号・中心・区画の形を読むだけ

### 15.11 状態の型（第 10 章に足す物）

```ts
type Minute = number; // 1 日目 0:00 からのゲーム内の分
type FieldId = 'prg' | 'lnx' | 'net' | 'sec' | 'db' | 'git' | 'ctr' | 'cld' | 'ci' | 'ai' | 'sta';

type TownRequest = Request & { client: number }; // 依頼主の建物の番号（15.3）

type Lot = { n: number; x0: number; z0: number; x1: number; z1: number; y0: number; road: number | null };
type Placed = {
	id: number;
	lot: number;
	kind: 'house' | 'shop' | 'park';
	startedAt: Minute; // 建ち始めた分。建ち終えるのは +60
};
type Road = { a: { x: number; z: number }; b: { x: number; z: number }; length: number };
type SystemBuilding = { field: FieldId; builtAt: Minute; links: number[] }; // つないだ依頼主の建物
type Box = { client: number; count: 1 | 2 | 3 };

type TownState = {
	version: 1;
	seed: number;
	minute: Minute;
	chapter: 1 | 2 | 3 | 4 | 'free';
	chapterStart: Minute; // その章の 1 日目 8:00
	freeRound: number; // 自由の章の何回目か（15.3）
	clientSat: number; // 依頼主の満足度（15.5）
	money: number;
	requests: TownRequest[];
	lots: Lot[]; // 始まりの区画 + 道沿いの区画
	zones: { lot: number; kind: 'home' | 'shop' }[];
	placed: Placed[];
	roads: Road[];
	systems: SystemBuilding[];
	boxes: Box[];
	satDelta: Record<number, number>; // 建物ごとの「要望」の項（15.5）
	rank: 0 | 1 | 2 | 3; // 町の格
	ledger: { at: Minute; text: string; v: number }[]; // 最近の出入り
	result: 'playing' | 'failed' | 'passed';
	grade: '合格' | '良' | '優' | null;
};

type TownAction =
	| Action // 段 4 の手（endDay は「明日の朝へ」で、tick の飛ばしに替わる）
	| { type: 'zone'; lot: number; kind: 'home' | 'shop' }
	| { type: 'park'; lot: number }
	| { type: 'road'; a: { x: number; z: number }; b: { x: number; z: number } }
	| { type: 'bulldoze'; id: number };

type TownSave = { version: 1; seed: number; now: Minute; actions: { at: Minute; action: TownAction }[] };

// 純粋な関数（DOM・WebGL・実時間を知らない。src/lib/game/）
// start(seed, map): TownState                        … 1 日目 8:00、朝の処理の後
// tick(state, to: Minute, map): { state; events }    … 毎時・朝・締めの処理
// apply(state, action, learned: Set<LessonId>, map): { state; event }
// replay(save, map): { states; events }              … 任意の時点を作り直す
// map は gen の決まった出力のうち、状態が読む物（建物の番号・中心・住む人・働く場所、始まりの区画、地形の高さ、道の交差点）
```

- 状態を決める処理に `Math.random`・`Date.now`・`performance.now`・`new Date` を使わない（段 8 の完成条件 2。8-2d でテストで確かめる）
- 見た目だけの動き（車・人・船・波・旗・砂ぼこり）は、種つきの擬似乱数と描画の時刻で動かしてよい（`city-standard.md` L-5）。状態には入れない
