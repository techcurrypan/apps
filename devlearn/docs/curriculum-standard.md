# カリキュラムの水準（D-23）

2026-11-18 の利用者の指摘「学習内容が簡易すぎる。ちょっと学ぶレベルではなく、技術を一から業界をリードできる、または人を育成できるレベル」を受けた、カリキュラムの基準。
**段 10-C（カリキュラムの作り直し）はこの全項目を満たすまで終えない。**

第 1 版のカリキュラム（`curriculum.md`。163 本）は「到達目標 1 つ・5〜9 ステップ・1 つの命令」に細かく割ったため、
「docker run で動かす」「止めて片付ける」のような、入口だけで終わるレッスンが並んだ。Kubernetes・システム設計・性能・障害対応の題も無かった。

## 3. 網羅の表（各分野で必ず教える題）

表の題は**必ずどれかのレッスンで、仕組みとして教える**（名前を出すだけでは足りない）。1 つのレッスンが表の複数の題を持ってよい。

### 3.1 `prg` プログラミング

値と型と表現（整数のビット・浮動小数の誤差・文字コード UTF-8）／変数と参照とコピー／制御と関数とスコープとクロージャ／
データ構造（配列・連結リスト・ハッシュ表の内部・木・ヒープ・グラフ）／計算量と O 記法の数え方／整列と探索／再帰と動的計画法／
メモリ（スタックとヒープ・GC の仕組みと停止）／例外と失敗の扱い／並行（スレッド・競合状態・ロック・デッドロック）／
非同期（イベントループ・Promise・async/await）／入出力とバッファ／正規表現の仕組み（バックトラックと爆発）／
テスト（単体・結合・テストダブル・境界値）／デバッグと計測（ブレークポイント・プロファイラ）／読みやすいコードとレビュー

### 3.2 `lnx` Linux

スケジューラとロードアベレージの読み方／仮想メモリ・ページキャッシュ・スワップ・OOM killer／
ファイルシステム（inode・リンク・マウント・ジャーナル）／権限（rwx・setuid・ACL・sudo・capabilities）／
シェル（パイプ・リダイレクト・終了コード・環境変数・クォート）／テキスト処理（grep・sed・awk・sort・uniq）／
systemd のユニットと journald／パッケージ管理／ホストのネットワーク（ip・ss・名前解決の順）／

### 3.3 `net` ネットワーク

UDP とポートとソケット／DNS（再帰と権威・キャッシュと TTL・レコードの種類・失敗の型）／TLS 1.3（ハンドシェイク・証明書の検証・SNI）／
HTTP/1.1・HTTP/2（多重化）・HTTP/3 と QUIC／プロキシと L4・L7 のロードバランサ／CDN／ファイアウォール／MTU と分割／
遅延と帯域と BDP の計算／パケットキャプチャの読み方（tcpdump・Wireshark）／届かない・遅いの切り分けの手順／
**Linux カーネルのネットワークの道筋（段 3・4。第 6.2 章の全項目）**：ソケットと sk_buff・送信の道（`tcp_sendmsg_locked` → `tcp_write_xmit` → `tcp_transmit_skb` → IP → qdisc → ドライバ → NIC）・

## 6. 実装の水準（段 3・4 の「中身」。D-23）

利用者は 2026-11-18 に、TCP の深さの例として「Linux カーネルの中の TCP の送信と受信の道筋」の図を示した（「例えば TCP は添付ファイルレベル」）。
**段 3・4 のレッスンの「中身」（`internals` のステップと詳しさ「中身まで」）は、この水準まで下りる。** 仕組みの説明で止めず、実際に動いている実装の中で、
**どの関数が・どのキューに・どの構造体を入れ・どの文脈で・次の関数を呼ぶか**を、層の図と動きで追う（`learn-standard.md` LS-D12〜D16・LS-M14・M15）。

- 示された図は深さの目安。**図そのものを写さない。** 名前と道筋は、版を決めた一次のソース（Linux なら kernel.org の版の tag のソース、Kubernetes なら版の tag のソース、
  PostgreSQL・Git も同じ）と公式の文書で確かめ、出典（`Source.kind = 'source'`、ファイルの道と行の範囲、版）を結ぶ
- 版を必ず書く（例：Linux v6.12）。版で名前や流れが違う所は「v5.x では …」と書く
- 関数名・構造体名・設定名は等幅で、本文と図と中身の板で同じ名前を使う

### 6.2 TCP の深さ（`net` の段 3・4 の必須。`learn-standard.md` 見本 1 と LS-Q14）

TCP を教えるレッスン群は、合わせて次の全てを、**層の図・キューの中身・動き・具体値**で教える。名前は版を決めた Linux のソースで確かめる。

| # | 教える物 | 見せ方の要点 |
|---|---|---|
| 1 | ソケットと `struct sock` / `struct tcp_sock`、`sk_buff`（skb）の形（head・data・tail・end、線形部と frags） | skb の箱を開くと各部が見える |
| 2 | 接続：`connect()` → SYN の skb を作り旗を立てて送る → SYN-ACK → ACK。状態（SYN_SENT → ESTABLISHED） | 接続の道筋を別の色で |
| 3 | 送信：`send()` → `tcp_sendmsg_locked()` が skb を作って送るデータを写し、**送信キュー**に入れる | プロセスの文脈。キューに箱が入る |
| 4 | `tcp_write_xmit()`：送信キューの先頭を覗き、送れる大きさを決め、**送るか待つか**（受信窓・cwnd・Nagle・TSO の待ち・TSQ の上限）を決め、skb の大きさを変える | 判断の札が 1 つずつ点く |
| 5 | `tcp_transmit_skb()`：skb を **clone** し、TCP ヘッダを付けて下の層へ。元の skb は**再送キュー**へ移る（ACK まで残る理由） | 箱が 2 つになり片方が下へ、片方が再送キューへ |
| 6 | IP 層と近隣（ARP）：経路を選び、IP ヘッダ、次の機械の MAC | 層の帯を降りる |
| 7 | qdisc：`fq_codel` と `fq`、EDT（skb の送る時刻）でのペーシング、backlog | qdisc の中で時刻まで待つ箱 |
| 8 | ドライバと NIC：送信リング、**TSO** で大きな skb が MSS ごとのパケットに割れ、MTU に収まる | 箱が割れる動き |
| 9 | 受信：RX 割り込み → softirq → **NAPI** のポーリング → **GRO** でまとめる → IP → `tcp_v4_rcv()` | 文脈が変わる所で矢印が途切れる |
| 10 | `tcp_rcv_established()` → `tcp_ack()`：ACK された skb を再送キューから外し、RTT を測り、cwnd を増やす。**送り待ちがあれば `tcp_write_xmit()` へ戻る** | 再送キューから箱が消え、数が変わる |
| 11 | 送信完了の割り込み → softirq：skb を解放し、**TSQ** で止めていた送りがあれば tasklet を予約し、`tcp_tsq_handler` から `tcp_write_xmit()` へ戻る | 待っている箱に時計の印、戻り道を別の色で |
| 12 | 実行の文脈：システムコール（プロセス）・hardirq・softirq・tasklet。ソケットをユーザーが持っている間の受信は backlog に入り、`release_sock()` で処理される | 文脈ごとの色と、途切れる矢印 |
| 13 | 失敗：パケットの喪失 → 重複 ACK で速い再送 / RTO での再送（再送キューから送り直す）、受信窓 0、qdisc とリングに溜まりすぎる（bufferbloat） | 箱が落ちる・溜まる・赤く止まる |
| 14 | 輻輳制御：CUBIC と BBR、cwnd とペーシングの関係 | cwnd の指標が動く |
| 15 | 運用：`ss -tim`（cwnd・rtt・retrans・unacked・notsent）、`nstat`、`tc -s qdisc`、`ethtool -k`（tso・gro）、`/proc/sys/net/ipv4/tcp_*`（`tcp_limit_output_bytes` など）、`net.core.default_qdisc`、bpftrace で `tcp_retransmit_skb` を見る | 端末の出力と図の数が一致する |
