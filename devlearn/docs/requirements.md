# devlearn 要件

IT を学ぶためのブラウザゲーム。**学んだ知識が、ゲームの中で使える手になる。**
旧 `swallow/devlearn-arena` とは別物として、一から作る。

---

## 0. 目的（G）

| ID | 内容 |
|---|---|
| G-1 | 手を動かして覚える。読むだけの教材にしない |
| G-2 | 説明は**1 ステップずつ進み、図が動き、値が見える**。どうなってどうなるかが目で分かる |
| G-3 | 学んだことがゲームの中で使える |
| G-4 | どの分野も、いつでも、どこからでも始められる |
| G-5 | 無料で運用し続ける。課金が自動で始まらない |

## 1. 前提・制約（C）

| ID | 内容 |
|---|---|
| C-1 | Svelte 5（runes）+ TypeScript strict + Vite + vitest |
| C-2 | `techcurrypan/apps` の `devlearn/`。公開先は Cloudflare Workers（`devlearn.techcurrybread.workers.dev`） |
| C-3 | 公開は GitHub Actions からのみ。検査を通らなければ公開されない |
| C-4 | 秘密情報をリポジトリ・配信物・`VITE_` に置かない |
| C-5 | カードを登録しない。無料枠を超えたら止まる側に倒す |
| C-6 | 絵は自作。他者の UI・絵・名称・意匠・コードを写さない |
| C-7 | **旧実装を参照しない・持ち込まない。** 例外は問題（`content-sources.md`）と、利用者が残すと決めた決まり（D-08） |
| C-8 | 旧 `swallow` リポジトリと、その GitHub Pages の配信を変えない・消さない |

## 2. 説明（E）

**中身の基準は `docs/explanation-standard.md` が正。** ここには要点だけを書く。

| ID | 内容 |
|---|---|
| E-1 | レッスンはデータ。型は `explanation-standard.md` 第 2 章で固定する |
| E-2 | 解説は 5〜9 ステップ |
| E-3 | 1 ステップに**図の変化・説明と具体値・記録 1 件**の 3 つを必ずそろえる |
| E-4 | どのステップの画面も、そのステップの状態だけから描ける |
| E-5 | **どうなって、どうなるかを動きで見せる。** 変化の前の状態 → 動き → 後の状態が見える |
| E-6 | **動きは何度でも繰り返し見られる。** そのステップに留まったまま再生し直せる |
| E-7 | `npm run content:check` が全レッスンを 15 項目で機械検査する。1 件でも落ちたら公開しない |
| E-8 | 既定は使う人が 1 つずつ進める。自動で流すのは補助 |

## 3. 学習（L）

| ID | 内容 |
|---|---|
| L-1 | 1 レッスンは 目的 / 前提 / 解説 / 例 / 実戦 / 確認 / 次 の 7 段 |
| L-2 | **ロックを作らない。** 前提は推奨として示すだけ |
| L-3 | 実戦は本物の道具を使う。本物を動かせない物は模擬を作り、本物と同じ出力・同じエラーを返す |
| L-4 | 打つコマンドが無い題材の実戦の形は、カリキュラム設計の段で一から決める |
| L-5 | 間違えたときは、なぜ駄目かと次の一手を返す（1 レッスンに 2〜4 件） |
| L-6 | 修了の記録はブラウザ内に保存する |

## 4. 分野（S）

| ID | 内容 |
|---|---|
| S-1 | **分野とレッスンはカリキュラム設計の段で一から決める。** 本数は設計の結果 |
| S-2 | 対象は「IT エンジニアとして仕事をするのに要る範囲」。最低限 Linux / ネットワーク / セキュリティ / データベース / Git / コンテナ / クラウド / CI / プログラミングの基礎を含む |
| S-3 | AI・機械学習（G 検定の出題範囲に沿う）を含む |
| S-4 | 統計（統計検定の出題範囲に沿う）を含む。どの級までをどう扱うかは設計で決める |
| S-5 | 1 レッスンは解説 5〜9 ステップに収まる大きさ。収まらないなら分ける |
| S-6 | 知識グラフ（推奨前提・関連・次に学ぶとよい）を、分野をまたいで張る |
| S-7 | 検定の公式の過去問・教材を写さない。公式との関係を騙らない |

## 5. ゲーム（B）

**`docs/game-design-brief.md` に沿って、ゲーム設計の段で一から決める。** ここで固定するのは次だけ。

| ID | 内容 |
|---|---|
| B-1 | 学んだ知識が、ゲームの中で使える手になる |
| B-2 | 学んでいなくても進める道が必ず残る |
| B-3 | 数字が動いたら「なぜ動いたか」を平易な言葉で示す |
| B-4 | 乱数で決めない。同じ種で同じ結果 |
| B-5 | ゲームの中で起きた変化も、**どうなってどうなったかを動きで見せ、繰り返し見返せる** |

## 6. 画面（U）

**画面の配置は、画面設計の段で一から決める**（`docs/screen-design-brief.md`）。
ここで固定するのは、分かりやすさの原理だけ（根拠は `docs/reference-analysis.md`）。

| ID | 内容 |
|---|---|
| U-1 | 一度に変わるのは 1 つ |
| U-2 | 変化が目に見える。物が現れる・動く・値が変わる |
| U-3 | 抽象の隣に、必ず具体値がある |
| U-4 | 1 つの出来事を、複数の表し方で**同時に**指す。表し方どうしが別の時点を指さない |
| U-5 | 今どこにいて、あとどれだけあるかが常に分かる。済んだ所に印 |
| U-6 | 速さを使う人が決める。進む・戻る・飛ぶ・**もう一度見る** |
| U-7 | 進んだ所までしか見せない |
| U-8 | 色は意味にだけ使う。色に頼らなくても区別できる |
| U-9 | 説明・実戦・ゲームが、同じ画面体系に収まる |
| U-10 | キーボードだけで操作できる |
| U-11 | ノート PC から携帯まで、画面幅で破綻しない |
| U-12 | 明暗の両方の配色を持つ |
| U-13 | 日本語のみ |
| U-14 | 参考サイトの配置・配色の値・絵・文言・題字を写さない |

## 7. MCP（M）

| ID | 内容 |
|---|---|

| ID | 内容 |
|---|---|

## 9. やらないこと（X）

| ID | 内容 |
|---|---|
| X-1 | 学習のロック |
| X-2 | 乱数で決める |
| X-3 | 他者の UI・絵・名称・意匠・コードの複製 |
| X-4 | 有料サービス・課金 |
| X-5 | 利用者登録・ログイン |
| X-6 | 多言語対応 |
| X-7 | 旧実装の参照（C-7 の例外を除く） |

## 10. 完成条件（A）

| ID | 確かめ方 |
|---|---|
| A-1 | push で検査が走り、通ったときだけ公開される |
| A-2 | わざと型の誤りを入れると検査で止まり、公開 URL は前の版のまま |
| A-3 | 全レッスンが `npm run content:check` を通る |
| A-4 | 任意のレッスンで、全ての表し方が常に同じステップを指す |
| A-5 | 任意のステップに飛んでも、戻っても、画面が正しい |
| A-6 | 任意のステップで、変化の前 → 動き → 後が見え、その動きを繰り返し再生できる |
| A-7 | どのレッスンも前提未修了で開ける |
| A-8 | 学ばずにゲームを進める道があり、実際に通せる |
| A-9 | 学んで戻ると、ゲームで使える手が増えている |
| A-10 | ゲームで起きた変化を、動きで繰り返し見返せる |
| A-11 | 同じ種で 2 回流して同じ結果 |
| A-12 | ノート PC と携帯の幅で崩れない。明暗の両方で崩れない |
| A-13 | `docs/screen-design.md` の原理対応表どおりに作られている |
| A-14 | リポジトリ・配信物に秘密情報が無い |
| A-15 | 旧実装のコード・本文が混ざっていない（C-7 の例外を除く） |
