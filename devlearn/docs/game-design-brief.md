# ゲーム設計の依頼書

ゲームの中身は**この文書に沿って設計段で決める。** ここでは決めない。
旧実装の設計（都市開発・市政・議員・政治資本など）は**参照しない。**

設計の結果は `docs/game-design.md` に書き、`docs/decisions.md` に決着として
残す。

---

## 1. 満たすべきこと（動かせない）

| ID | 内容 |
|---|---|
| B-1 | **学んだ知識が、ゲームの中で使える手になる。** 学習が飾りにならない |
| B-2 | **学んでいなくても進める道が必ず残る。** 学習をロックや必須条件にしない |
| B-3 | 数字が動いたら「なぜ動いたか」を平易な言葉で示せる |
| B-4 | 乱数で決めない。同じ種で同じ結果 |
| B-5 | 1 回の遊びの単位が短い（数分）。途中で閉じても状態が残る |
| B-6 | 絵は自作で描ける範囲にする。写実や大量の素材を要する設計にしない |
| B-7 | 既存のゲームの仕組み・名称・意匠を写さない |
| B-8 | ゲームの中で起きた変化を、**どうなってどうなったか動きで見せ、繰り返し見返せる** |

## 2. 決めること

1. **題材** — 何を育てる／運営するのか。学びが交渉や判断の材料になる題材を選ぶ
2. **1 回の行動** — プレイヤーが毎回する操作は何か
3. **抵抗** — 思いどおりにならない相手は何か。なぜ抵抗するのか
4. **学びの効き方** — 学んだ知識が、どの場面で、どう手として現れるか
5. **学ばない道** — 学ばずに進む手段は何か。その代償は何か
6. **進み方** — 何が増え、何が解放され、どこで一区切りつくのか
7. **失敗** — 失敗は何か。やり直せるか
8. **画面に要る物** — ゲームのために、常に見えていなければならない物は何か。
   配置は画面設計の段で決めるので、ここでは「何が要るか」だけを書く

## 3. 決め方

- 案を **3 つ**作る。それぞれ 1 ページで、1〜8 を埋める
- 各案について、B-1〜B-8 を満たすかを表で判定する
- **選んだ理由と、落とした案を落とした理由**を書く
- 選んだ案を `docs/game-design.md` に詳細化する

## 4. 詳細化で書くこと

- 状態の型（TypeScript）。モデル層は DOM を知らない
- 1 ターン（または 1 日）の処理の順序
- 数式。**全ての数字に、なぜその値かの根拠**を書く
- 学びが効く場面の一覧。どのレッスンがどの手に対応するか
- 学ばない道の一覧と代償
- ゲームのために画面に要る物の一覧（配置は書かない）

## 5. やらないこと

- 利用者登録・ログイン
- 課金・外部の有料サービス
- 実在の人物・団体・製品の名前
- ライセンス不明の素材
