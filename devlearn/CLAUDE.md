# devlearn の規則

この規則は、ほかの全てに優先する。迷ったらここに戻る。

## 1. 一から作る

旧 `swallow/devlearn-arena` の**コード・設定・本文・カリキュラム・ゲーム設計・
画面設計・進め方の決まりを、参照しない・持ち込まない。**

例外は 2 つだけ。

- **問題（設問と選択肢）** は過去の資料から取ってよい。`docs/content-sources.md` に従う
- **利用者が残すと決めた決まり**（`docs/decisions.md` の D-08）は要件に入っている。
  それ以外の旧版の決まりは、似た物を思い付いても、要件に無ければ入れない

旧リポジトリと、その GitHub Pages の配信は、変えない・消さない。

## 2. 根拠は仕様書だけ

`docs/requirements.md` と `docs/plan.md` に無い機能・画面・要素を、
ほかの経緯から持ち込まない。足したくなったら `docs/decisions.md` の未決に書き、
`DECISIONNEEDED` で止まる。

## 3. スタック

- Svelte 5（runes。`$state` / `$derived` / `$effect` / `$props`）
- TypeScript strict。`any` を置かない
- Vite / vitest
- 配信は Cloudflare Workers（静的アセット ＋ Worker）
- Svelte 4 までの書き方（`export let`、`$:`、ストアによる状態）を使わない

## 4. 配信

- 公開は GitHub Actions からのみ。手元から `wrangler deploy` を打たない
- 検査が通らなければ公開されない形を保つ
- 作った物は公開 URL で確かめる。`https://devlearn.techcurrybread.workers.dev`

## 5. 秘密情報

- 鍵・トークン・パスワードを、リポジトリ・コミットの説明文・配信される
  ファイルに書かない
- **`VITE_` で始まる環境変数はブラウザに埋め込まれる。** 秘密情報を入れない
- コミット前に `npm run secrets` を通す

## 6. 無料

- Cloudflare にカードを登録しない。無料枠を超えたら止まる側に倒す
- 有料のサービス・部品を使わない

## 7. 権利

- ライセンスが不明な素材を使わない。絵は自作（ゲームの街はプログラムで作る 3D。外部の 3D 素材・画像を持ち込まない）
- 既存のゲーム・サイトの UI・絵・模型・コード・固有の意匠・名称を写さない。
  参考サイトからは原理だけを取る（`reference-analysis.md`）
- 例外：ライセンスが明示的に許す公開物（Astryx、MIT）は、画面設計の段の判定を経て
  見た目の土台に使ってよい（D-07）。ライセンス表示を守る
- 実在の人物・団体・リーグ・選手の名前を使わない
- 検定の公式の過去問・公式教材の文・図・表を、そのまま写したり言い換えたりして
  使わない。公式の認定・提携・合格保証を思わせる表現、ロゴ・意匠を使わない

## 8. 動きと再現

- **乱数で決めない。** 同じ種から同じ結果。`Math.random` と `Date.now` を
  状態を決める処理で使わない
- **どの時点の画面も、その時点の状態から描ける**こと。巻き戻し・飛び越し・
  繰り返し再生の土台になる
- **どうなって、どうなるかが動きで分かる**こと。変化の前と後を見せる
- **動き（アニメーション）は何度でも繰り返し見られる**こと

## 9. 学習

- **ロックを作らない。** 前提未修了でも開ける。前提は推奨として示すだけ
- 1 レッスンは 7 段（目的 / 前提 / 解説 / 例 / 実戦 / 確認 / 次）
- 実戦は本物の道具を使う。本物が動かせない物は模擬を作り、
  本物と同じ出力・同じエラーを返す
- 間違えたときは、なぜ駄目かと、次の一手を返す
- 知識グラフ（推奨前提・関連・次に学ぶとよい）を持つ
- **説明の中身は `docs/explanation-standard.md` に従う。**
  `npm run content:check` を必ず通す

## 10. ゲーム

- 具体の仕組みは `docs/game-design-brief.md` に沿ってゲーム設計の段で決める
- **舞台は 3D の港町づくり（D-14）。** 見た目とゲーム性は `docs/city-standard.md` を満たし、
  試作 `docs/prototype/minato.html` と同等以上にする。簡素な図・札だけの画面にしない
- 試作 `docs/prototype/` は 2026-11-10 に一から作った物で、旧実装ではない。**段 8 はこの試作のコードを土台にする**（D-16）。
  一から書き直さない。試作のファイルは比べる相手なので、消さない・書き換えない
- 見た目だけの動き（車・人・船・波・旗）は、状態を変えないので、種つきの擬似乱数と描画の時刻で動かしてよい。
  状態（資金・人口・満足度・需要・区画・建物・要望）を決める処理には使わない
- 次は要件として固定する
  - 学んだ知識が、ゲームの中で使える手になる
  - 学んでいなくても進める道が必ず残る
  - 数字が動いたら「なぜ動いたか」を平易な言葉で示す
  - 乱数で決めない
  - ゲームの中で起きた変化も、どうなってどうなったかを繰り返し見返せる

## 11. テスト

- 先に失敗するテストを書いてから実装する
- 完成条件の 1 つずつに、どう確かめたかを記録する

## 12. 記録と進め方

`loop.ps1` が次の決まりに依存しているので守る。

- 段ごとに `docs/progress/phase-<N>.md` に記録する（次の実行はこれを読んで続きから進める）
- 決まったことは `docs/decisions.md` に追記する
- 調べた外部仕様・無料枠は、確認日と出典を書く
- 全部終わったら `ALLDONE`、決められない事が出たら `DECISIONNEEDED` とだけ出力する
- `docs/plan.md` 段 8-2f（利用者に街を見てもらう所）では、決められた通りに未決を書き、`DECISIONNEEDED` で止まる

## 13. やってはいけないこと

- 完成条件を満たさないまま次の段へ進む
- 段 8 で試作を使わずに街を一から書き直す。試作より見劣りする物を完成とする
- 段 8 を、利用者が「良い」と書く前に終えたことにする
- 旧実装を参照する・持ち込む（例外は第 1 章の 2 つだけ）
- 学習にロックを作る
- 乱数で決める
- 他者の意匠・名称・コードを写す
- 仕様書に無い機能・画面を足す
- 秘密情報を置く
- 旧 `swallow` リポジトリと配信を変える・消す
