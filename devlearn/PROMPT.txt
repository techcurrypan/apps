【毎回まず】
  1. 公開が止まっていないか確かめる（CLAUDE.md 第 4 章・D-24）。公開 URL の一番下の「配信：」と origin/main の最新コミットが違う、
     または GitHub Actions の最新の Deploy devlearn が失敗なら、何より先に直して公開を通す
  2. docs/decisions.md の「利用者の指摘」を読む。未対応（[ ]）があれば、今の段より先にそれを直し、
  直したら [x] にして、どう直したかを 1 行書き添える

【やること】
  - docs/plan.md の、終わっていない最初の段を進める
  - 先に失敗するテストを書いてから実装する
  - 小さく作る。意味のある単位でコミットする
  - 検査を通す
      npm run check / npm run lint / npm run test / npm run content:check
      npm run secrets
  - git push して、公開 URL で自分の目で確かめる
      https://devlearn.techcurrybread.workers.dev
  - docs/progress/phase-<N>.md に記録してコミットする
      何を作ったか / どう確かめたか / 満たした完成条件 /
      満たせなかった物とその理由

【終わり方】
  - その段の完成条件を全部満たしたら、次の段へ進む
  - 全部終わったら ALLDONE とだけ出力して終われ
  - 確認を求めるな。止まるな。最後の段（段 12）まで進める
  - 仕様書で決まっていない細部は、仕様書の目的に一番合う案を自分で選び、
    docs/decisions.md の「自分で決めたこと」に、選んだ案と理由を書いて進む（CLAUDE.md 第 2 章）
  - CLAUDE.md 第 2 章の 3 つの場合だけ、docs/decisions.md の未決に
    「問題 → 影響 → 変更案」を書いてコミットし、DECISIONNEEDED とだけ出力して終われ
